# Builtin PNG source precision

The static, nonindexed PNG entrance retains original color samples before applying color management. It normalizes eight-bit values by 255 and sixteen-bit values by 65535. For an embedded ICC profile, it sends these RGB float samples to the selected CMS with a linear-sRGB destination. This path uses builtin, Little CMS, or ColorSync through the same profile facade. The presence of liblcms2 does not determine which engine evaluates an embedded ICC profile.

Successful conversion produces extended linear RGB: negative and above-one components remain available for composition and later processing. Untagged opaque eight-bit images retain the ordinary byte path. Sixteen-bit samples and alpha processing use float storage. Selected gAMA/cHRM uses the same CMS profile facade with or without liblcms2; converting the resulting frame to an encoder working view can consume a color-conversion slot in the worker budget. Tests of scheduling without color conversion explicitly disable CMS. The byte-only keycolor optimization excludes sixteen-bit input even with CMS disabled, so a keycolor setting cannot silently reduce color or alpha to eight bits.

These contracts apply to `sixel_frompng_load_nonindexed()` in [frompng.c](../../../src/frompng.c), also used for an embedded PNG raster in BMP. Indexed palette conversion retains its separate byte boundary. Builtin APNG now reuses this original-sample decoder for linear RGB plus a separate continuous alpha plane; its inter-frame and delivery contracts are defined separately. See the [PNG loader overview](png/README.md).

## Source selection and fallback

The [shared metadata policy](../png-color-metadata.md#source-interpretation-policy) remains in force. In particular, the coexistence of iCCP, sRGB, and cHRM selects sRGB, while iCCP plus sRGB without cHRM still selects the applicable ICC profile. CMS disabled means these metadata transforms are disabled. Builtin requires usable gAMA before using isolated cHRM; cHRM alone retains its default sRGB interpretation. The libpng cHRM-only numeric expectation is therefore not the builtin expectation.

A usable gAMA remains applicable when cHRM is singular or numerically unusable and no higher-priority iCCP/sRGB interpretation applies. Both opaque and alpha-bearing canonical inputs then use independently decoded gamma samples. The PNG selector classifies this metadata before attempting an allocation-dependent profile factory. A NULL returned while constructing a valid profile is a different failure: it does not grant the new opaque gamma fallback.

The canonical failure policy applies in both builds. If a valid profile cannot be created or applied, an opaque input retains its original source samples; the alpha path may use gAMA when sRGB is absent. Both the image and its file background return to their original samples before that decision. This makes factory/apply failure observable in no-libLCMS gAMA/cHRM paths that formerly used a local evaluator without those failure boundaries. Metadata rejection remains distinct from a valid-profile CMM failure. Historical metadata scanning boundaries remain build-dependent: no-libLCMS stops at IEND and requires usable cHRM/gAMA payload lengths for presence; the libLCMS build retains its raw flags and late-chunk behavior. Acceptance is not PNG conformance validation.

## Chromaticities and numerical boundaries

The PNG selector retains cHRM as original unsigned integers on its 1/100000 grid for metadata validation. It checks bounds before computing `Z = 100000 - X - Y` and divides integer X and Z by integer Y. A valid primary with X+Y=100000 therefore has exact Z=0; floating subtraction must not turn it into a negative residual. The source matrix must be invertible, its primary scales positive, and its Bradford cone divisors and resulting coefficients finite and usable. Invalid chromaticity metadata does not become valid through an epsilon or by clipping a transformed pixel.

Selected gAMA/cHRM is represented as a shared gamma/chromaticity source profile and evaluated by the requested CMS, including ColorSync in a no-libLCMS build. The facade owns source primaries, white-point adaptation and destination conversion. The loader retains only normalization, metadata validation and transfer decoding needed by unmanaged or failed-transform composition. It does not run a second local profile matrix after a CMM failure. The retained palette and APNG helpers keep bounded gamma RGB8 output and their existing alpha/canvas behavior.

Actual `LSXCMS2|event=apply` records identify the evaluator separately from parser and `event=source-profile-adapter` diagnostics. A selected engine name alone does not establish that conversion ran. Successful builtin and native conversions are checked against the same independently derived source values with their separately stated numerical budgets.

The independent [metadata fixtures](../../../tests/data/color-numeric/png-metadata.json) record original chunks, samples, alpha, background and each expected storage boundary. Direct fallback decoding retains exact final F32 expectations; selected-CMS observations use the existing source-derived budgets. A native calibrated profile can serialize XYZ/TRC values to ICC fixed-point fields before evaluation; that serialization and native transform error are separate from the original PNG definition. Neither supplies a replacement oracle. The existing native subnormal and cancellation limitations are not extended by these integer-source checks.

The palette byte helper stages the entire RGB buffer before either embedded-ICC or chunk-profile conversion and publishes only after success. Allocation, profile creation, or prefix-write failure therefore retains every original RGB component. Invalid cHRM in the no-libLCMS byte path selects a gamma-only profile through the facade; a failed valid-profile transform does not authorize that alternate source interpretation.

The palette helper uses the canonical linear-sRGB CMS destination, then applies the signed sRGB transfer, stores gamma float32 and clips/rounds only when publishing bytes. A native gamma destination can introduce a different gamut/transfer mapping; it must not change the interpretation of the same palette samples. Builtin byte observations retain exact nearest-byte expectations. The ColorSync palette observation checks adjacent integer candidates derived from the continuous Decimal sRGB result: `[floor(255*x), ceil(255*x)]` after clipping to the representable interval. This is a finite fixture contract, not a fitted tolerance around measured native bytes or a universal one-byte CMS accuracy guarantee. Native float accuracy and actual engine application have separate observations; final image quality remains a separate gate.

## Alpha, background, and target

Alpha is coverage from the original integer sample. It is never passed through a color TRC. Linear RGB composition occurs after source interpretation, and zero-alpha coverage remains a separate mask according to the selected transparency policy. Hidden RGB and the mask follow the same orientation transform.

File bKGD values use the same selected profile as the image. Both transformations must succeed before their results can be used together. If image conversion succeeds and background conversion fails, or the reverse, both return to their original integer samples before the same fallback decision. An explicit background instead uses its declared gamma/linear definition and is never passed to the source ICC profile. The original decoder buffers remain alive until conversion and composition finish.

The requested `cms_target` is applied after composition. A gamma float view retains extended values through the signed sRGB transfer. An explicit RGB888 view widens the canonical float sample to double, evaluates gamma in double, then clips and rounds at the byte boundary. It does not store an intermediate gamma float value. Both a preliminary linear byte view and a gamma float store can change the final byte. For example, the independently derived gAMA case maps the original sixteen-bit sample 33524 with gAMA=45455 to linear float 0.22884844243526459. Its gamma value rounds directly to byte 132; first storing gamma as float gives 0.5156862735748291 and byte 131. A caller that explicitly requests a gamma float view still receives that float value. The independent [PNG target fixtures](../../../tests/data/color-numeric/png-byte-target.json) record the original samples and each storage boundary.

## Independent numeric checks

The [source fixture generator](../../../tools/generate_color_fixtures.py) uses original integer RGB/alpha samples, stored ICC coefficients, and independent Decimal matrix/TRC calculations. The existing map8 ICC probe is also derived from its original RGBA8 samples, its stored 1024-point curv table, and its stored XYZ matrix; [its manifest](../../../tests/data/color-numeric/legacy-png-icc.json) records the unchanged image/profile hashes and computed expectations.

Builtin and Little CMS cases compare the requested output against independent source-derived values. ColorSync canonical samples are checked against the independent ICC expectation with its native linear tolerance. For ColorSync target cases, a first load must pass that canonical check with identical source, engine, background, alpha, and orientation settings. Independent signed-TRC and byte-rounding equations then project those validated native float samples to the requested target. This separately checks CMS linear accuracy and target conversion; it does not claim the final gamma value has the same absolute error bound as linear RGB.

## Test coverage

This ledger covers the builtin **PNG loader**, including cases that select builtin, Little CMS, or ColorSync as the CMS engine. A builtin-loader pass is not automatically a test of builtin-CMS arithmetic, and a builtin-CMS test through libpng does not prove this loader entrance. The [complete builtin-loader inventory](../../testing/builtin-loader-coverage.md) classifies assertion mechanisms for its directory; the source-precision contracts below also own tests in the separate loader-unit category.

### Assertion boundaries

| Observation | Evidence and limit |
| --- | --- |
| Original samples and CMS values | The behavioral tests compare inspected source/frame values with the independent expectations described above. Some require exact binary32 or byte results; native transformations use their stated numerical tolerances. Neither is an MS-SSIM assertion. |
| Alpha, metadata, target, and failure recovery | Direct mask, metadata, callback, engine-trace, and restored-sample assertions protect the named boundary. The same fixture can support several distinct assertions without making their guarantees interchangeable. |
| Encoded-image quality | The shared PNG quality matrix protects perceptual floors separately. A quality pass cannot replace a source-sample, extended-range, or actual-engine check. |
| CLI through SIXEL | Frame probes stop before encoder resize, palette construction, and 101-level wire rounding. Output invariance protects the compared behavior, but two paths can share the same arithmetic error. The focused CLI contract below adds its own independent RGB101 and coverage assertions for one selected path; the source/frame tests retain their broader numeric ownership. |
| Expected-value derivation | Fixture regeneration checks consistency with the generator. A separately implemented oracle or a source-byte causal experiment provides additional evidence and should not be counted as another normal runtime test unless it is registered as one. The [independent oracle audit](../libpng.md#independent-oracle-audit) preserves the rational-certificate and exhaustive UINT16 checks; it does not execute this decoder. |

Each numeric observation verifies the declared frame format/colorspace, all RGB samples, exact zero-alpha coverage, and the selected evaluator's actual apply events. The paired failure tests include the production PNG implementation in a separate namespace and supply original integer samples through a decoder double; the public loader observations independently exercise actual PNG decoding. Factory NULL, image-prefix failure, background-prefix failure and metadata rejection remain distinct. Component allocation and callback-failure tests use the real loader and require balanced ownership; they do not claim to audit every internal allocation of an external CMM.

### CLI numeric and structural tests

The exclusive builtin PNG loader and actual builtin CMS convert the existing 4x2 RGB16 Display-P3 ICC/alpha fixture to an 8x4 nearest-resampled frame over explicit black. The scalar float/Heckbert/gamma/no-dither path is compared with [independently derived RGB101 expectations](../../../tests/data/color-numeric/cli-color-wire.json). Palette selection is resolved at paint time, then all final pixels, four retained alpha-zero holes, raster dimensions and P2=1 are checked. This finite sRGB wire regression complements the source/frame expectations and MS-SSIM floors; it does not qualify Display-P3 device output or the full encoder policy space.

### Quality regression tests

The [shared decoded RGB matrix](../png-color-metadata.md#decoded-rgb-matrix-contracts) owns the metadata reference-image tests, which compare decoded samples numerically rather than by MS-SSIM. Additional builtin PNG/APNG quality cases are identified by assertion mechanism in the [builtin-loader inventory](../../testing/builtin-loader-coverage.md). They are separate from the source/frame expected-value tests above, even when they use the same PNG metadata or CMS setting. Neither a perceptual floor nor a byte-equality comparison between two encoder runs is an independent numerical CMS oracle.

### Coverage boundary

Run the relevant cases with the builtin loader selected explicitly and with both liblcms2-enabled and disabled builds. Both now apply selected profiles through the shared facade, while their historical metadata scanning boundaries remain distinct. An unavailable external engine is a skip, and resolved-engine settings alone do not prove execution; engine-specific tests require actual apply records. Static nonindexed source contracts do not qualify all builtin formats, every ICC dialect, or every animation composition case. Fault-injection and restoration assertions protect their stated failure boundaries; archived mutation/build evidence is revision-specific and does not substitute for registered tests.
