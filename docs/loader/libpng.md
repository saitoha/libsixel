# libpng Image Loader

The `libpng` loader decodes PNG scanlines with the external libpng library and implements APNG playback in [`loader-libpng.c`](../../src/loader-libpng.c). libsixel owns frame representation, color management, alpha/background normalization, orientation, and delivery. An APNG-patched libpng is not required.

The [selected Display P3 output path](../encoder/output/output-colorspace.md#display-p3-selected-cpu-float-path) connects opaque static RGB samples through builtin CMS, the selected CPU float quantizers and exact lookup to final P3 RGB101 SIXEL. Its explicitly selected libpng cases do not extend this guarantee to every source domain or encoder policy.

## Origin and stages of support

The initial libpng reader was developed with [yaft's source](https://github.com/uobikiemukot/yaft) as a reference, as recalled by libsixel's maintainer. The [2014-10-20 introduction](https://github.com/saitoha/libsixel/commit/1dc22c25810f08c345be36e707abe76b9970e16e) records the implementation in `converters/loader.c`; that commit establishes the date and initial behavior, while the yaft attribution comes from the maintainer's account. This is the origin of the PNG adapter, distinct from the [SIXEL encoder's lineage](../project-history.md#kmiyas-sixel).

Support grew in stages. Using libpng for raster decoding did not immediately provide all of libpng's sample formats, transparency behavior, color management, or animation through libsixel's frame API.

## Selection and supported input

Enable the optional dependency with Autotools `--with-png` or Meson `-Dpng=enabled`. `HAVE_LIBPNG` controls registration, and libpng is first in the compiled default loader order. Use `-Llibpng!` to close the chain and inspect this component alone; `-Llibpng` permits other configured loaders after an eligible failure. Check the running binary's help and loader trace rather than inferring selection from a `.png` filename. The build dependency also enables the [PNG writer](../writers/png/README.md), which is a separate component.

```sh
img2sixel -Llibpng! input.png
img2sixel -Llibpng:cms_engine=builtin:prefer_8bit=0! input.png
img2sixel -Llibpng! -S --start-frame=1 animation.png
```

Quote `!` in shells with interactive history expansion. Build tools should use the repository's `.local/bin` first in `PATH`.

The predicate recognizes the eight-byte PNG signature. libpng handles DEFLATE, row filters, Adam7 interlace, and standard PNG samples: grayscale at 1/2/4/8/16 bits, indexed at 1/2/4/8 bits, and RGB, grayscale-alpha, and RGBA at 8/16 bits. The effective decoder feature set depends on the linked libpng build. This adapter does not implement Apple `CgBI`, HDR tone mapping or interpretation of `mDCV`/`cLLI`. Supported SDR cICP tuples use the [shared PNG source policy](png-color-metadata.md#cicp-source-definitions). See the [PNG specification](https://www.w3.org/TR/png-3/) and [libpng manual](https://github.com/pnggroup/libpng/blob/libpng16/libpng-manual.txt) for codec-level details.

## Processing boundaries

| Stage | Responsibility |
| --- | --- |
| Original chunk classification | Validate chunk boundaries and animation structure without allocating a canvas or copying image data. Recognize actual chunk types, not matching bytes inside payloads. |
| Static decode | Read the original stream through `png_read_image()` and `png_read_end()`. Retain eligible packed palettes and grayscale formats, or expand to component samples. |
| APNG rectangle decode | Reconstruct a PNG for each controlled rectangle, carrying shared metadata including `PLTE`, `tRNS`, color chunks, and `bKGD`; use the same sample/CMS processing as static PNG. |
| Color interpretation | Convert validated supported source metadata to linear sRGB while keeping alpha separate. |
| Composition | Resolve the requested background and alpha policy. APNG first updates its linear RGB/alpha canvas, then prepares the emitted frame. |
| Delivery | Attach zero-alpha coverage, apply orientation, and invoke the callback. Once a callback has been invoked, an error is terminal for the loader chain. |

`SIXEL_TRACE_TOPIC=loader` shows candidate selection; `apng_decode` shows animation parsing and replay. Static inputs bypass animation decoding and ignore animation start-frame settings, including malformed or out-of-range environment values.

## Color management and precision

The CLI defaults to `cms_engine=auto`; a directly constructed component starts with CMS disabled until configured. Decoder choice and CMS-engine choice are independent. `png_source_to_linear()` supplies the same source interpretation to static images and animation rectangles. The [shared CMS policy](color-management/README.md) owns engine selection, rendering-intent fallback, target colorspace, and unsupported-profile behavior.

The [common PNG metadata precedence](png-color-metadata.md) owns the ColorSync-compatible source choice, including the `iCCP+sRGB+cHRM` coexistence rule. The adapter retains original pre-IDAT sRGB/cHRM declarations because libpng can hide conflicting declarations in its metadata getters. This does not authorize reordering late metadata or reviving rejected profiles: only ICC bytes exposed by libpng after validation are eligible. A failed supported ICC transform is traced and falls back to supported lower-level metadata. Alpha remains linear coverage and never enters CMS.

For a cHRM definition exposed by the external floating getter, the adapter reconstructs its 100000-scale integers and classifies each white/primary XYZ numerator on that grid. A zero numerator is accepted; a negative numerator or invalid coordinate rejects the matrix. After those coordinate checks, the matrix builder rejects exactly collinear primaries using an int64 signed area from the original grid, before floating inversion. Nonzero areas of either sign remain eligible for the arithmetic policy below. The [PNG metadata policy](png-color-metadata.md#libpng-integer-grid-boundary-contracts) owns the original-sample and file-background contracts, and the [boundary test plan](../testing/png-chrm-boundaries.md) distinguishes exact grid checks from component-level numeric checks. Builds without the optional libpng fixed-point API use the same floating getter. Getter-rejected cHRM is never restored from raw chunks.

Original eight- and sixteen-bit samples are normalized before managed color conversion and alpha composition. The ICC destination is linear sRGB, so native extended gamma output is not reinterpreted using a different transfer extension. Managed output, including indexed PNG, retains negative and above-one components in float32 instead of being re-encoded through the source byte buffer. This promotion follows the source metadata even without a float preference hint. Sixteen-bit samples retain their low bits; a transparency optimization does not truncate them. Grayscale ICC conversion also has an internal float gray format in [`cms.c`](../../src/cms.c), including the builtin, Little CMS, and ColorSync format mappings. This is an internal conversion format, not a new public PNG or frame format.

Static opaque images without an applied metadata transform may retain byte RGB, packed indices, or grayscale storage. After source conversion and alpha composition, the requested CMS target determines working coordinates; an explicit `prefer_8bit=1` remains a bounded gamma RGB representation. For that byte request, the frame setter widens canonical float samples and evaluates the gamma transfer in double before final clipping and rounding. The caller does not insert a gamma float view: that extra rounding can cross a half-byte boundary. For example, direct gAMA=45455 and the original sixteen-bit sample 33524 produce byte 132, while an intermediate gamma float store would produce 131. An explicitly requested gamma float view retains its own float storage semantics. The independent [PNG target fixtures](../../tests/data/color-numeric/png-byte-target.json) fix these separate values for direct gAMA builds without liblcms2; the alternative chunk-profile policy remains covered by the source CMS tests. Unmanaged eight-bit alpha with no resolved background retains byte RGB plus a zero-alpha mask, or RGBA8 in the existing keycolor path. Static untagged images also avoid a temporary full RGB float allocation merely because CMS is enabled. Composition and managed alpha paths emit linear RGB float32 plus a zero-alpha mask. APNG uses float32 linear RGB and fractional alpha internally and emits linear RGB float32 frames plus masks. Subsequent encoder precision and quantization choices remain separate, explicit boundaries; see [pixel-format precision](../concepts/pixelformat-precision/README.md).

The `SIXEL_LOADER_LIBPNG_USE_TRNS_KEYCOLOR` compatibility switch may select an eligible representation optimization. It does not grant permission to discard alpha, change background priority, or reduce sixteen-bit precision. CMS or indexed expansion must preserve coverage regardless of that switch.

### Indexed palette precision

A successful palette ICC, gAMA or cHRM conversion retains the converted entries in a temporary linear float palette, then expands the decoded indices to a linear RGB float frame. CMS runs on the palette entries once, before expansion. Negative values, values above one and sub-byte fractions survive this boundary. The frame does not carry an eight-bit palette; requested CMS target coordinates are applied afterwards through the same frame conversion as nonindexed input. This does not introduce a public float-palette representation.

Packed 1/2/4-bit indices respect each decoded row's padding, including odd widths and Adam7 output. Eight-bit indices use the same float entries. CMS-disabled inputs, untagged inputs, sRGB-only inputs and rejected metadata with no applicable fallback retain the original palette and avoid a full RGB float allocation. A byte preference does not suppress a required CMS promotion; the loader-specific `prefer_8bit=1` is a separate, explicit bounded output request. Indexed tRNS and background composition retain the existing component-alpha path and coverage semantics.

### cHRM arithmetic selection

`libpng:chrm_arithmetic=auto|double|512bit` (short key `A`) controls only the libpng loader's selected cHRM transform, including APNG rectangles and file-background colors. The default is `auto`. `SIXEL_LOADER_LIBPNG_CHRM_ARITHMETIC` supplies the environment default; an explicit suboption wins. Empty or invalid environment values retain `auto`, while an invalid CLI value is rejected. The builtin decoder and other loaders do not accept this suboption. `img2sixel` and `lsqa` use the same loader syntax.

| Mode | Construction and pixel evaluation | Guarantee |
| --- | --- | --- |
| `auto` | Classify the matrix once; use double for ordinary denominators and the bounded 512bit integer evaluator for small denominators. | A routing policy, not a correct-rounding guarantee for every accepted color. |
| `double` | Build double coefficients and use a direct three-term dot product. | Ordinary arithmetic in the normal nearest-even floating environment; strongly cancelling inputs can lose accuracy. |
| `512bit` | Build exact rational coefficients using sixteen 32-bit integer words, evaluate the rational dot product, and round directly to binary32 with ties to even. | Correct rounding for this bounded transform and its supported binary32 input representation. This is not a general high-precision floating-point library. |

The routing threshold is `1e-5`, with strict comparison on the original integer grid. For primary signed area `A`, the test is `abs(A) / 100000^2 < 1e-5`. For a required source-white Bradford cone `q`, scaled by the integer Bradford matrix below, it is `abs(q) / (10000 * white_y) < 1e-5`. Equality remains double; both signs use the same magnitude rule. Exactly zero area or a required zero cone remains undefined metadata and follows the existing transfer fallback before arithmetic selection. These thresholds do not claim LittleCMS equivalence or measure the error of an individual pixel. Auto never switches modes by inspecting a pixel's cancellation or a per-pixel error enclosure.

The input to this evaluator is the existing transfer-decoded float32 RGB value in `[0,1]`. The exact guarantee starts at those float bits, after sample normalization and nonlinear transfer decoding. It does not cover earlier transfer-function rounding, later alpha composition, palette reduction, SIXEL encoding, arbitrary ICC profiles, or other CMS engines. Negative and above-one results of the matrix remain representable in float32 for downstream gamut handling. No new general CMS API is introduced.

Exactly equal RGB channels preserve their float32 gray value, including white and subnormal gray; signed zero becomes positive zero. Near-gray values use the selected evaluator without a gray tolerance. This shortcut follows the standard target and white-adaptation definition below. Direct double multiplication is the ordinary colored-pixel rule: centering every color on one channel can introduce additional cancellation or lose a much smaller channel and is not uniformly better.

A supported, selected 512bit request that cannot be provided fails with `SIXEL_NOT_IMPLEMENTED`. It does not silently retry with double or permit another loader to turn that availability failure into success, even when the order has no trailing `!`. In contrast, a PNG whose selected source is ICC, sRGB, or transfer-only metadata has no selected cHRM arithmetic request to satisfy; forcing `512bit` does not make that otherwise valid input fail. CMS disabled also bypasses this setting.

### cHRM target definition and white adaptation

The target definition is independent of the arithmetic choice. Linear sRGB is defined here by D65 white `(0.31270, 0.32900)` and primaries R `(0.64000, 0.33000)`, G `(0.30000, 0.60000)`, B `(0.15000, 0.06000)`. The exact inverse of the RGB-to-XYZ matrix derived from these coordinates replaces rounded decimal inverse coefficients at this PNG boundary. A matching sRGB source therefore has an exact identity matrix. This target-definition correction is separate from adding arithmetic modes.

For a different source white, the PNG transform applies Bradford adaptation to D65 before the standard sRGB inverse. The Bradford matrix is the exact rational matrix with integer rows `(8951, 2664, -1614)`, `(-7502, 17135, 367)`, `(389, -685, 10296)`, divided by `10000`. With source matrix `S`, standard target inverse `T`, and source/target white vectors `Ws` and `Wd`, the result is `T * inverse(B) * diag((B*Wd)/(B*Ws)) * B * S`. Matching D65 skips adaptation. Introducing this chromatic adaptation changes interpretation for non-D65 cHRM sources independently of the arithmetic used to evaluate it; the source-only control and D50 tests in the [arithmetic test plan](../testing/png-chrm-arithmetic.md) keep these changes distinguishable. This PNG work does not change the general builtin ICC or builtin PNG decoder transforms.

### Arithmetic trace and validation boundary

`SIXEL_TRACE_TOPIC=loader` emits `PNGCHRM1` with `role=image|background`, requested and selected modes, actual evaluation (`identity`, `double`, or `512bit`), the construction reason (`forced`, `ordinary`, `small-area`, `small-cone`, or `small-area+cone`), and counts of identity, double, and integer pixels. An identity-only batch can select 512bit without performing an integer dot product. Non-applicable cases report `actual=not-applicable` and the metadata or CMS reason instead of claiming that a transform ran.

The [independent fixture generator](../../tools/generate_png_arithmetic_tests.py) uses Fraction Gaussian elimination and a separate direct binary32 rounding routine. Ordinary P3, D50-adapted P3, and primary-permutation vectors retain the existing absolute numeric budget of `2e-7`; exact-path tests compare all float bits, and white/gray contracts have separate exact tests. This numeric budget is not a perceptual image-quality score. Separately certified nonneutral tiny vectors and the chosen dispatch-boundary vector have one float32 rounding cell under an independent double forward bound and therefore require exact output bits in all three requested modes. Real loader callback tests inspect tiny float32 frames through explicit options and environment defaults before quantization; see the [numeric certificate contract](../testing/png-chrm-arithmetic.md#ordinary-double-value-certificates). A [16-by-16 snake conversion regression](../../tests/cli/options/regression/0167_loader_libpng_chrm_arithmetic_image_regression.t) also verifies identical short-option/environment output and an MS-SSIM floor of 0.98. It guards that fixture's final encoded quality, not every possible profile or image.

## Alpha and background

The [alpha policy](alpha-policy/README.md) and [background policy](background-policy.md) apply to static PNG and APNG alike. `file_first` selects valid bKGD before the external candidate; `explicit_first` reverses that order. If the preferred source is absent, use the other available source. No source means no background, not implicit black.

File background samples use the image's source interpretation, including indexed palette lookup and applicable CMS. An external background uses the requested `background_colorspace`: `gamma` decodes it as sRGB and `linear` uses its values directly. This setting describes external sample encoding; composition itself uses linear light in both cases. An OSC 11 reply is a gamma-encoded external candidate as specified by the shared policy.

For foreground color `F`, resolved background `B`, and alpha `a`, composition computes `a * F + (1 - a) * B` in linear RGB. `composite` fills alpha-zero pixels when a background exists and clears their mask. `clear` and `keep` preserve zero-alpha coverage, while partial alpha can still use an available background. Unresolved `composite` preserves coverage so the encoder can request `P2=1`. Without a background, partially covered static pixels retain their source color because SIXEL cannot encode fractional alpha.

Expanding an indexed image because of requested colors, disabled palette fusion, CMS, or composition carries tRNS into the expanded samples. Retained indexed images can use a transparent index, remapping multiple zero-alpha entries to one index; expanded images use component alpha or a mask. The encoder consumes this coverage metadata and selects the wire request. A fully opaque emitted APNG canvas does not need a transparency header merely because its source color type has an alpha channel.

To compare against an independently generated opaque reference, make the intended composition explicit:

```sh
img2sixel -Llibpng:cms_engine=none! -Acomposite -B#000 -Nexplicit_first input.png
```

## APNG semantics

An IDAT default image belongs to the animation only when fcTL precedes it. Otherwise all of its IDAT chunks are excluded from the declared animation count, output callbacks, and frame numbering. Animation sequence numbers, frame counts, rectangles, operation values, and chunk ordering are checked before delivery. Applicable pre-IDAT metadata, including tRNS, is included in each reconstructed rectangle PNG. Color chunks appearing after the original IDAT are not moved ahead of a reconstructed rectangle to make them usable.

The canvas stores straight alpha and linear sRGB. `SOURCE` replaces the controlled rectangle. `OVER` combines foreground and destination with their fractional alpha and normalizes by the resulting coverage. `BACKGROUND` disposal clears the rectangle to transparent; it does not paint bKGD. `PREVIOUS` restores the saved canvas. The selected background is applied to an emitted copy, leaving fractional canvas alpha available for subsequent frames.

Until a rectangle carries color metadata other than an sRGB identity, has a bit depth above 8, or carries alpha other than zero and one, every canvas value is the linear sRGB decoding of a source byte. While that holds, each emitted frame is re-encoded to RGB888, matching the [builtin APNG byte canvas](builtin/png/README.md#apng-pipeline) and keeping later stages on byte arithmetic; after it fails once, this and every later frame of the animation are emitted as linear float RGB. Color metadata keeps the float canvas even when CMS is disabled, because the source bytes are then not sRGB values to restore.

Delay fractions are converted to integer centiseconds; a zero denominator uses 100 and a positive fraction that truncates to zero becomes one centisecond. `-l disable` emits one pass; `-l auto` follows the play count, where zero permits indefinite replay. A one-frame animation stops after one pass. `-g` controls later presentation waiting.

`--start-frame`/`-T` overrides `SIXEL_LOADER_ANIMATION_START_FRAME_NO`. Negative indices count from the declared end. Earlier frames still update the canvas, but their first-loop callbacks are skipped. Subsequent loops start from the beginning, and emitted frame numbers are local to each loop. `-S` stops after the selected callback. The original chunk structure and relevant CRCs have already been checked, but compressed pixels of later frames need not have been decoded; successful extraction is not exhaustive raster validation of the whole animation.

## Integrity, errors, and resources

The classifier checks chunk boundaries, IHDR placement, contiguous IDAT, IEND, and the animation grammar. IEND CRC is checked explicitly because libpng can treat its CRC failure as a warning. Before APNG reconstruction, the adapter validates original critical and animation-control/data CRCs. Replacing fdAT with newly checksummed IDAT cannot conceal an original CRC error. Optional ancillary chunks retain libpng's recoverable warning/skip behavior; success does not mean every ancillary checksum was accepted as valid.

Each libpng reader uses its own jump target. Cleanup retains its owned pointers across error unwinding. A failed decode or a callback error returns its status; the [loader manager](README.md#candidate-selection-and-fallback) may try a different backend only before the first callback. It never appends replacement frames after delivery has begun.

APNG storage includes two float RGBA canvases, the reconstructed compressed frame, decoded color/alpha buffers, emitted frames, and an optional replay cache. The cache budgets retained frame storage at 64 MiB. Allocation failure or budget exhaustion disables retention and permits later loops to decode again, with the same pixels, masks, timing, and order. This is not a total-memory limit or a public cache-size suboption. Dimension and reconstruction-size arithmetic are checked before allocation.

Static classification does not allocate either animation canvas or rebuild IDAT chunks. Performance comparisons should still separate libpng raster work from adapter parsing, CRC, allocation, CMS, and encoder work. The [recorded static measurements](builtin/png/README.md#measured-static-png-cost) describe an earlier adapter and must not be presented as measurements of this implementation or as a codec ranking.

### Coverage boundary

Run the category with `HAVE_LIBPNG=1` and with both Little-CMS-enabled and disabled builds. Builtin-only skips do not validate this adapter. The numerical probes deliberately use small independently constructed inputs, including low-bit pairs, fractional blends, and a valid gray ICC profile. Broader encoded-output and MS-SSIM comparisons do not replace those exact observations. The [shared PNG color-metadata document](png-color-metadata.md#test-coverage) owns the cross-decoder matrix and exact CMS-priority probes.

The suite does not exhaust every color-type/depth/interlace combination, every ICC dialect or engine-specific rounding rule, all eight orientations, or the exact 64 MiB cache boundary. The cache allocation probe covers initial pointer-array allocation failure and selected samples, masks, timing, and numbering; it does not prove complete frame equality, partial-cache cleanup, or the size boundary. Occupied-canvas restoration, original fdAT checksums, and static/late-APNG libpng raster error unwinding have dedicated probes. The older short malformed-stream probe remains supplementary and does not itself exercise longjmp. External terminal rendering and OSC 11 round trips remain outside these in-memory tests. Byte composition is covered by LP-21's numerical contract.

### Independent oracle audit

`make staticcheck` runs `staticcheck-png-color-oracles` and `staticcheck-tiff-uint16-oracles`; both are also available as individual [Autotools and Meson targets](../testing/staticcheck.md#running-the-target). An inconsistent expectation fails the suite. The checks use only the host Python standard library and run even when optional PNG, TIFF, or CMS components are disabled.

Run `python3 tools/verify_color_oracles.py --kind png` from the source root to check the stored [arithmetic certificates](../../tests/data/color-numeric/png-arithmetic-certificates.json). The [auditor](../../tools/verify_color_oracles.py) uses exact rational Cramer's-rule/cofactor calculations instead of the fixture generator's Gaussian solve, independently decodes and rounds binary32 values, and checks both endpoints of each certified error enclosure. It checks the stored dispatch, tiny-input, and original-integer loader certificates without calling a fixture generator, loader, or CMS. The arithmetic TAPs remain responsible for comparing the implementation with those expectations.

Running the auditor without `--kind` also exhaustively checks all 65,536 UINT16 normalization values and MINISWHITE complements, plus the stored separate-plane TIFF source tables for orientations 1–4. This calculation verifies expected-value data separately from the per-image runtime tests. It is neither an MS-SSIM test nor a claim that every TIFF layout or alpha ratio has been executed. Historical mutation runs and build identities qualify a particular reviewed revision; they do not add current runtime coverage to this ledger.
