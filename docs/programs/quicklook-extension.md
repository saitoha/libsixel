# SIXEL Quick Look extension

The macOS extension lets Quick Look preview and thumbnail providers decode `.six` and `.sixel` files for Finder and other Quick Look clients. It is an optional companion program, disabled by default. The [Quick Look input loader](../loader/quicklook.md) instead asks installed providers for a preview to feed into `img2sixel`; enabling that loader does not install this extension.

## Components and requirements

The implementation in [quicklook-extension](../../quicklook-extension/) targets macOS 10.15 or newer with an Objective-C compiler and the Apple QuickLook, QuickLookThumbnailing, Cocoa, CoreGraphics and related system frameworks. The deployment target in the compiled Mach-O is determined by the selected compiler/SDK flags and can be newer than the plist minimum; choose and inspect that target before distribution. Configuration checks the available APIs; the broader [platform matrix](../platform-support.md) does not imply that every extension deployment path is exercised.

`SixelQuickLookHost.app` contains `SixelPreview.appex` and `SixelThumbnail.appex`. `SixelPreviewBridge.app` provides the file-opening bridge, and `register_sixel_preview` sets Launch Services handlers. The bundles declare the `com.saitoha.libsixel.sixel` type for `.six` and `.sixel`. Their SIXEL decoding core is compiled into `libsixelquicklookcore.a` and linked into the providers and bridge, with external image libraries disabled; they still depend on macOS frameworks. The archive is a build artifact, not a separate runtime dependency.

## Autotools build and installation

From a configured source/build tree on macOS:

```sh
./configure --enable-quicklook-extension
make
make install
```

The option defaults to `no` in [configure.ac](../../configure.ac), independently of `--enable-quicklook-preview`. [quicklook-extension/Makefile.am](../../quicklook-extension/Makefile.am) assembles both apps under `quicklook-extension/products/` and produces `quicklook-extension/package/SixelQuickLook.pkg` during the normal build.

The extension part of `make install` invokes the common [package management wrapper](../../tools/quicklook-extension.bash), which calls `/usr/sbin/installer -pkg <finished-package> -target /`. The native helper validates the published package and manifest hashes first. It never copies apps directly, signs installed code, runs user registration, chooses a user from environment variables, changes a default handler or resets caches/services. Installer itself may cause OS discovery of installed apps; system installation does not claim that a user has activated the providers. Insufficient privileges return status 77 with an administrator command, without invoking sudo or a password dialog. Installer's nonzero status is returned unchanged by the helper; build runners may report their own enclosing failure status.

The explicit `install-quicklook-extension` target uses that same operation. `installcheck-quicklook` runs the independent installed TAP observations; normal top-level `installcheck` includes the same observations through the common installed-command harness. They do not build, install or repair anything. Missing installation or a pending/unreadable operation lock fails; nonempty DESTDIR (or `SIXEL_INSTALLCHECK_DESTDIR` for observation only) prints an explicit STAGING skip, which is not evidence of system installation. These checks do not establish GUI activation or rendering.

### Distribution staging and dry-run

With a nonempty `DESTDIR`, installation only stages `SixelQuickLook.pkg`, `payload-manifest.json`, `package-evidence.json` and the native management tool at `${DESTDIR}${datadir}/libsixel/installers/`. A `.quicklook-stage.json` records those owned distribution files. No system payload is expanded, Installer or receipt command is run, or user registration/default/cache/service is changed. Staging mutations require absolute DESTDIR and datadir paths without `..`; internal spaces are preserved, empty DESTDIR selects system installation, and the wrapper rejects a whitespace-only relative staging destination. GNU Make can trim a whitespace-only command-line variable assignment to an empty value: use an absolute staging path. Read-only installcheck skips for any nonempty staging variable without accessing that path. Symlinked destination ancestors are refused, including `/tmp`; use its canonical `/private/tmp` path on macOS.

DESTDIR uninstall checks the complete staged inventory and hashes, removes only matching files and the empty installers directory, and retains shared parents. Changed, extra, missing or symlinked stage contents are refused before deletion. A failed stage write can leave an incomplete distribution requiring operator inspection; it is not silently adopted or recursively erased on retry. `make -n install`, Meson `install --dry-run`, and the wrapper's `--dry-run` do not perform OS installation. The wrapper dry-run returns before executing even the native helper.

### Ownership, exclusion and removal

The [native management implementation](../../quicklook-extension/Sources/SixelInstall.h) shares the package's manifest and receipt checks. Managed install and uninstall atomically acquire `/private/var/run/libsixel-quicklook-managed.lock` as an outer operation guard. Managed install holds it before invoking Installer until its child exits successfully and the exact receipt and installed payload pass final validation. Managed uninstall holds the same guard through removal and receipt absence verification. Concurrent managed calls fail immediately with `wait=0`, including the interval between postinstall, receipt commit and the final check. Read-only installcheck refuses either pending guard or package lock.

Package preinstall independently acquires `/private/var/run/libsixel-quicklook.lock` before preflight. Postinstall verifies installed bytes/attributes and releases only that package lock. A normal standalone Installer.app or `/usr/sbin/installer` installation therefore requires no additional completion command and leaves no project lock after successful completion. Package scripts do not release or adopt a managed caller's outer guard. A standalone Installer has no outer guard: concurrent managed administration after its postinstall and before its receipt commit is outside this exclusion guarantee. Run standalone Installer and managed operations separately. This limitation does not apply to concurrent managed install/uninstall calls, which remain excluded until their caller's final checks finish.

There is no timeout-based or PID-based stale-lock deletion. A package preflight failure releases only its package lock. A managed install child failure, exception or final validation failure retains its outer guard for operator inspection, even if no package lock remains; a nonzero child status does not prove that no mutation occurred. Managed uninstall precondition failures release their own acquired locks, while failures after deletion starts retain recovery evidence. Original Installer/receipt failure status is preserved. Package interruption before successful postinstall can leave its package lock; standalone failure after postinstall may leave an inconsistent receipt/payload without a project lock and requires explicit inspection. Never treat absence of a lock as installation success. No helper provides a transaction covering unrelated macOS Installer activity.

`make uninstall` delegates the extension portion to `uninstall-quicklook-extension`. System removal requires root, the exact expected distribution manifest and receipt, complete unchanged owned trees, and an explicit declaration that all affected users have already restored their settings: set `QUICKLOOK_USERS_DEACTIVATED=yes` for the explicit target, or pass `--users-deactivated` to the wrapper. This declaration is an administrator prerequisite, not automatic proof of user deactivation. No user is inferred or edited. Absent receipt and absent destinations are idempotent; residual unowned files, unexpected children, changed payload, or a different expected distribution fail. Only manifest-owned files and empty owned directories are removed, with `unlink`/`rmdir`, followed by `pkgutil --forget` for the exact receipt and an absence query. Shared parents and `~/Applications` are never deleted. Failure after deletion starts leaves receipt/lock evidence for recovery; no recursive cleanup or repair is attempted.

Before system work, preserve the original distribution package, payload/receipt evidence, shared parent attributes and each participating user's registration/default state in a managed environment. After a failure, stop competing operations, inspect the remaining payload/receipt and lock identity, and arrange explicit restoration or removal. Never blindly remove a lock to force a retry. Automatic repair and adoption of unknown per-user copies are unsupported. The explicit user operations, owned-copy archive/restore and sequential lifecycle interfaces below are separate from system install; the legacy `--products-dir`/`--user-home` copy/delete interface is rejected. Real Installer transitions and restoration must be validated independently of private fixture tests.

## Meson build boundary

The corresponding opt-in is:

```sh
meson setup builddir -Dquicklook_extension=enabled
meson compile -C builddir
```

`quicklook_extension` defaults to `disabled` in [meson_options.txt](../../meson_options.txt), independently of `quicklook_preview`. [quicklook-extension/meson.build](../../quicklook-extension/meson.build) builds the standalone decoder archive, four executables, registration helper and generated plists. The [bundle producer](../../quicklook-extension/products/meson.build) assembles both app trees under the build directory's `quicklook-extension/products/` during a normal build. `meson compile -C builddir quicklook-extension-bundles` selects that producer and the registration helper explicitly. Each copied executable and plist is a dependency, so clean out-of-tree and parallel builds do not rely on source-tree products.

Both build systems use [assemble-bundles.sh](../../quicklook-extension/assemble-bundles.sh) to copy completed native executables and plists into fresh bundle trees. Assembly does not sign or register the apps; any later signing must consume these completed outputs after binary modification. The extension cannot be combined with the executable shebang-prefix option: prepending a script header does not preserve a native Mach-O bundle executable. A changed executable, generated plist or assembly script invalidates the producer. Deleting files inside an otherwise unchanged generated directory requires rebuilding the bundles from a clean output; directory timestamps alone are not an integrity check.

`meson install -C builddir` calls the same wrapper with the same finished package, privilege and DESTDIR contracts. It does not install app trees or the registration helper separately. The explicit `install-quicklook-extension`, `uninstall-quicklook-extension` and read-only `installcheck-quicklook` run targets select the corresponding operations. The generic `installcheck` run target runs the extension observations before its installed CLI tests, independently of CLI selection. Meson's standard `uninstall` does not invoke custom install scripts and therefore does not remove the system package or custom staged distribution: use `meson compile -C builddir uninstall-quicklook-extension` with the same DESTDIR when staging, or the documented user-deactivation prerequisite for system removal. This limitation is not reported as successful package removal. Build-system dry-run semantics follow [Meson's install-script contract](https://mesonbuild.com/Reference-manual_builtin_meson.html#mesonadd_install_script).

## Installed observer input contract

`make installcheck-quicklook` and `meson compile -C builddir installcheck-quicklook` execute the [installed TAP suite](../../tests/extension/quicklook-installed/) without requiring installed converters. The normal top-level `installcheck` also selects that suite, alongside its existing installed converter checks. These entries do not build or install the package; create the enabled distribution first. Ordinary `make check` and Meson TAP runs report these cases as installcheck-only skips. `DESTDIR` or `SIXEL_INSTALLCHECK_DESTDIR` reports STAGING before accessing the observer, expected files or OS. Disabled/unsupported configurations and cross execution have distinct skip reasons. An enabled system installation with missing receipt or payload fails; all-skipped runs are not installation evidence.

The build-tree `sixel-quicklook-package installed OBSERVATION DIRECTORY CONTEXT` is a read-only observer. `DIRECTORY` defaults in the TAP harness to `quicklook-extension/package` and contains the distribution's `payload-manifest.json` and `package-evidence.json`. `QUICKLOOK_EXPECTED_DIR` explicitly selects a preserved distribution instead. The manifest must match the distribution evidence hash, pass the package manifest contract and be separate from the installed manifest. This is an integrity comparison to a caller-trusted distribution, not authentication of an arbitrary supplied directory. Package archive/evidence/payload consistency is owned by the package suite. No result is accepted solely because the installed manifest describes its own files.

The independent system observations cover exact receipt identifier/version/volume/location, each of the four bundle paths, each bundle's full recursive path/type/mode/hash inventory, the support tree, six code signatures and their distribution identities, and installed manifest bytes/mode/ownership. The Host inventory includes its nested extensions; the separate Preview and Thumbnail observations identify their own failures. The support inventory includes both helpers. Root:wheel checks apply on the actual system root. Symbolic links in owned trees or ancestors and either outstanding operation lock are rejected. These observations share the package manager's inventory, signature and receipt primitives without performing an installation preflight or repair. Observations are independent reads, not an atomic OS transaction; concurrent external administration can invalidate a snapshot.

User observation is explicit. Without `QUICKLOOK_USER_CONTEXT`, only user cases skip with a system-only reason; this does not imply activation, preservation or successful rendering. With a context, unavailable/mismatched UID or GUI session is a failure. The observer never impersonates a user. Its real/effective UID must match the positive, explicitly supplied UID and console UID; its Security session ID must match and have graphic access without the remote flag. Run it within that user's GUI session. A historical snapshot or environment-derived HOME is insufficient.

The read-only JSON context has `format: 1`, `mode: "activated"`, numeric `uid` and `session`, and `manifestSHA256` for the exact expected distribution. `before` and `owned` dictionaries carry the relevant historical and intended values, keyed by `election:preview`, `election:thumbnail`, `default:six` and `default:sixel`. Election records contain identifier, version, UUID, original path, canonical path and election (`+`, `-`, `!`, `=`, `?` or `default`). Default records contain the resolved UTI, handler ID (or explicit null) and application identity including path, canonical path, ID, version and signature/CDHash. Known absence is an explicit null handler with an empty application object; an election before-value may use the exact object `{"absent": true}`. Other incomplete identities fail. The observed current value must equal `owned`; before evidence must exist. This comparison does not authenticate a journal writer, prove that an operation occurred or authorize restoration. Missing/incomplete journal identity fails, rather than becoming a preservation claim. Activation, separate default changes, journal writing, conditional deactivation/restoration and explicit lifecycle orchestration belong to the user-operation layer and are not implemented by installcheck.

Launch Services observations query candidate URLs with `LSCopyApplicationURLsForBundleIdentifier`, retain original and canonical paths, and require the expected system instance with matching installed plist version/ID and distribution code identity. Separate per-bundle duplicate observations require exactly one candidate; an old app or build-tree copy with the same ID cannot substitute for the system instance. PlugInKit observations run only `pluginkit -m -A -D -v -i ID`, retaining every reported version/instance, UUID and election. The verbose format is parsed strictly as four tab-separated fields; an unfamiliar format or query failure is an observation failure, never absence or success. A blank election is reported as `default`. Registration and election describe database state, not proof of the provider chosen by a rendering client. No registration, election, handler setter, receipt mutation, cache reset or service termination is invoked.

`sixel-quicklook-package user-state` prints a version-1 JSON snapshot of the caller's UID/session, Host/Bridge candidate records, Preview/Thumbnail instance records and the independently resolved `.six`/`.sixel` defaults. It writes only stdout and performs fresh queries; redirect it to a private evidence file when needed. Two extensions are observed independently because the installed database can resolve them to different UTIs. Before/after snapshots surrounding a complete installcheck audit registration/default stability; equality over that interval does not establish long-term restoration or causation for unrelated concurrent OS changes. User-operation workflows must retain before/owned/current evidence and exact distribution identity, refuse ambiguous or insufficient identity before mutation, and re-observe current state before considering any conditional restoration. A system-only check needs no journal and never claims user preservation. User-only TAPs emit a zero-plan SKIP before launching the observer when no context is supplied; a supplied malformed or wrong context remains a failure.

Each TAP invocation includes native process startup, expected-input validation, all required live queries, hashing/signature validation, assertions and output in its normal harness time. Package generation, private fixture preparation and optional full snapshots are separate shared work, not cached substitutes for required per-case assertions. Autotools retains `quicklook-extension/installcheck/quicklook-installcheck.log` and per-case `.log`/`.trs` copies outside generic runtime-log cleanup; top-level `make testtimecheck` includes that report when present. Meson retains the independent stage in `meson-logs/quicklook-installed-installcheck.json` (and `.txt`), separately from the generic stage's `testlog-installcheck.json`. Custom log bases also retain the setup suffix. Preserve completed reports before a selection overwrites them. Run the manual [timing check](../testing/guide.md#post-run-interpretation) after changing tests and retain first/repeated values and all overruns. The test-only `QUICKLOOK_OBSERVER_PATH` allows explicit private compiled boundary controls; the shipped executable has no runtime alternate-system-root or OS-command override. Fixture positives are not actual Installer, user activation, restoration or Finder evidence.

The enabled extension stage cannot be excluded by Autotools `TESTS` or Meson `SIXEL_INSTALLCHECK_TESTS`. The numbered installed inventory is selected independently, and an unexpectedly empty Autotools inventory is an error. The generic stage excludes those observations to avoid duplicate execution. The dedicated installed entry runs already-configured TAP drivers only: missing observers or distribution inputs fail without compiling programs, producing binding/PSD fixtures, installing or repairing anything. Log collection is shared reporting work and does not remove required API queries or assertions from any measured test.

## Installer package construction

When the extension is enabled, both normal builds run the native [package tool](../../quicklook-extension/Sources/SixelPackageTool.m) after assembly. `pkgbuild`, `productbuild`, `pkgutil`, `lsbom`, `codesign`, and Xcode CLT's `lipo` and `otool` are required; the shared [prerequisite check](../../quicklook-extension/check-package-tools.sh) reports missing tools during configuration. No third-party Installer authoring software, Python runtime, release certificate or root privileges are required. Disabled configurations do not perform these package tool checks or generate a package. Reconfiguring an enabled directory to disabled can retain old artifacts; absence must be observed in a separately prepared fresh build.

Use `--with-quicklook-package-version=1.0.0` with configure or `-Dquicklook_package_version=1.0.0` with Meson to set the distribution build number; both default to `1.0.0`. The accepted form is three canonical decimal integers, with major 1–9999 and minor/patch 0–99. Raise this number for every changed distribution payload, including a different architecture. The four final `CFBundleVersion` values and component package version use this number. `CFBundleShortVersionString` uses the validated numeric release portion of the upstream version; the complete upstream string remains in the manifest as source provenance. A timestamp or dirty Git state never silently assigns a distribution number.

The package contains these fixed system-relative trees, under one receipt identifier `com.saitoha.libsixel.quicklook.pkg`:

- `/Applications/SixelQuickLookHost.app`, including Preview and Thumbnail extensions;
- `/Applications/SixelPreviewBridge.app`;
- `/Library/Application Support/libsixel/QuickLook/`, containing `payload-manifest.json`, the native package/preflight tool, and `register_sixel_preview` (not executed during construction or preflight).

The producer copies the assembly outputs into its private `package/work/root` before changing distribution plists and signing. The original `products/` executables and generated plists retain their assembly identity, so their byte-comparison tests remain applicable. Every packaged executable is inspected across its Mach-O slices: architecture sets must match, only macOS load commands are accepted, and runtime dylib/rpath references outside `/usr/lib/` and `/System/Library/` are rejected, including private build prefixes and sanitizer runtimes. Supported architecture names are `arm64` and `x86_64`; execution on untested architectures is not established by packaging. The highest actual minimum OS across all packaged code, with a floor of 10.15, becomes every final bundle's `LSMinimumSystemVersion` and the product's allowed OS minimum. The product also declares the actual architecture set and system-only Installer domain. These declarations describe binary requirements; they do not establish runtime compatibility on older systems.

Signing proceeds from inner Preview/Thumbnail extensions to Host, then Bridge and the auxiliary executables. Each signing invocation runs in a dedicated `/bin/sh` child that sets umask 022 and immediately executes `codesign`, with arguments passed separately from the fixed shell command. The parent never changes its mask, so restoration is unnecessary even on failure and unrelated packaging operations keep the caller's mask. All four `Contents/_CodeSignature/CodeResources` files must be regular files with mode 0644 before manifest creation and archiving; their modes are never repaired after signing. The extension signatures use the declared [sandbox entitlements](../../quicklook-extension/Resources/QuickLookExtension.entitlements). The builder verifies code signatures before writing a manifest of fixed relative paths, kinds, modes, SHA-256 file hashes, bundle identity/version, architecture, minimum OS and signature identifiers/CDHashes. Symbolic links and unsupported file types are rejected, including symlinked destination ancestors during preflight. Payload verification enumerates the actual trees, uses `lstat` for numeric type/mode/ownership without following links, and hashes every regular payload file. Missing ancestors are allowed for a new destination; other ancestor stat errors are refused. The full inventory and comparison execute inside each observation; no prior successful result is cached. The manifest excludes its own hash. Its private staging file is explicitly set to mode 0644 before copying into package scripts or archiving, independent of the caller's umask; existing assembly files and signed code are not chmodded. The Bom inspection requires this fixed manifest mode. `package-evidence.json` records the external manifest and package hashes, plus a format-2 inventory of every expanded path, node type, mode and regular-file SHA-256 (including Distribution, PackageInfo, Bom, Scripts and Payload). Signed payload is never modified afterward.

Both builds currently produce **ad hoc signed code inside an unsigned development package**. This is not Developer ID distribution, notarization or Gatekeeper approval. Release distribution needs a separate qualified signing pipeline using Developer ID Application for code, Developer ID Installer for the final package, and notarization. Changing signatures changes payload identity: regenerate the manifest and package after code signing, and do not mutate the signed bundle afterward. Certificate acquisition, notarization submission and release publication are not implemented by this producer. Apple's [packaging guidance](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution) distinguishes these code and container signatures.

`pkgbuild` receives explicit non-relocatable, strict-identifier, version-checked, whole-bundle `upgrade` component policies for all four bundles. `productbuild` creates the distribution archive with explicit domains, OS and architecture requirements, following Apple's [Distribution XML reference](https://developer.apple.com/library/archive/documentation/DeveloperTools/Reference/DistributionDefinitionRef/Chapters/Distribution_XML_Ref.html). The builder expands the actual package with `pkgutil --expand-full`, verifies its payload and manifest identity, checks the resulting PackageInfo/Distribution and final signatures, then publishes the package last. The expanded archive under `package/work/expanded` is a declared shared build artifact for read-only observations; expansion is not performed inside each test. The publication correspondence observation reads and hashes the current public archive and manifest, enumerates and hashes the full expansion, and compares all three with the same evidence record. Missing or replaced archives, changed evidence or manifests, stale expansions, and altered metadata/scripts fail this observation without rebuilding or repairing anything. Evidence binds the producer's completed expansion to the archived bytes; it is local provenance, not a cryptographic attestation against deliberate replacement of the whole package/evidence set. A build may regenerate missing outputs; use `meson test --no-rebuild` or already-built Autotools test log targets when testing rejection of an existing mismatch. Removing an internal output requires an explicit package rebuild for repair.

The package explicitly sets `overwrite-permissions="false"` in the component `PackageInfo`. Shared parent records in the Bom describe defaults for newly created directories; they must not replace the owner, group or mode of existing `/`, `/Applications`, `/Library`, `/Library/Application Support` or `/Library/Application Support/libsixel`. The builder uses `pkgutil --expand` (without expanding Payload), edits only this metadata attribute, and uses `pkgutil --flatten` before `productbuild`. Signed payload bytes and the original Bom remain unchanged. The expanded real archive must declare this preservation policy, and its Bom must contain only the expected payload and shared parent records, with root:wheel ownership and the declared file types/modes. Manifest validation independently requires each of the four signature resources at mode 0644, so matching manifest and Bom entries at 0600 cannot satisfy the distribution contract. Optional AppleDouble records must correspond to an expected path with matching attributes. Owned directories use mode 0755. Existing owned trees must match their recorded payload; real system preflight also refuses owned directories with a different owner/group, rather than using permission repair scripts. A package that would require changing retained owned directory attributes is not an automatic upgrade.

Apple's [Software Distribution Legacy Guide, File Permissions](https://leopard-adc.pepas.com/documentation/DeveloperTools/Conceptual/SoftwareDistribution4/SoftwareDistribution4.pdf#page=79) describes preserving existing directory permissions when overwriting is disabled. This is historical authoring guidance, not proof of modern Installer execution. Verification here inspects the actual PackageInfo/Bom and signed payload. Successful signature verification as the extraction owner does not establish readability by an installed ordinary user; the fixed resource mode is a separate distribution requirement. Actual installed-user signature verification and launch remain untested here; a managed installation test must still compare shared parent owner/group/mode before and after installation and upgrade, including deliberately customized parent attributes.

The embedded [preinstall script](../../quicklook-extension/package-preinstall) acquires the operation lock and invokes the same native tool's read-only state check. It refuses non-system target volumes, unowned occupied destinations, receipt/manifest version or location disagreement, changed/missing/extra owned payload files, downgrades, and same-version distributions with a different manifest. Identical-payload reinstallation and higher-version payloads require the current owned trees to match their recorded manifest; automatic repair and adoption of existing copies are unsupported. Shared parent directories are not owned. The state check does not modify user registrations, defaults or caches; only its operation lock is created by the script wrapper. The pure state checker supports private fixture roots for regression tests, while the Installer entry fixes the root at `/` and reads the exact receipt with `pkgutil`.

Package generation and archive inspection do not run Installer or launch the applications. The install integration above is separate from package construction. Metadata and private-root checks do not establish actual installation, upgrade/downgrade refusal, rollback, ordinary-user signature verification, shared-parent preservation or user activation on the machine. Full installed-state and lifecycle verification remain separate from the focused read-only manifest/receipt check.

## Use and validation boundary

After installation, select a SIXEL file in Finder and request Quick Look (Space), then inspect its thumbnail separately. Opening a file uses the bridge and handler association. Quick Look caches, provider enablement, signing and the active user session can affect these observations; log out and back in when checking a changed registration. Verify both the installed paths and rendered content before claiming successful deployment.

## CI and manual validation boundary

The [CI lifecycle contract](../ci/design.md#quick-look-package-lifecycle-validation) owns the two explicitly enabled build jobs, disposable-runner prerequisites, required-system-test skip rejection and cleanup/error handling. It reuses the package wrapper, installed observer and explicit lifecycle; it does not enable the extension in ordinary jobs or add user activation to normal installation. A CI definition or private fixture PASS is not an executed Installer/provider/GUI result.

Finder Space preview, list thumbnail and Bridge open are three distinct manual observations. They remain unverified without an approved managed environment, exact package/version/installed identities, target UID/GUI session, a current before snapshot and a concrete preservation/restoration plan. Read-only installation and registration observations and offline rendered-image checks cannot replace those observations. Existing user choices and legacy copies must be preserved; do not reset caches or registrations merely to obtain a passing result. The explicit user/lifecycle operations below provide mechanisms, while real OS restoration remains a separate validation obligation.

## Explicit rendering diagnostics

Both enabled builds provide the build-tree `quicklook-extension/sixel-quicklook-render` diagnostic. Live generation never runs automatically during build, check or installcheck, and the tool is not included in the signed package. Live generation is an explicit operation for an approved test user/environment: `sixel-quicklook-render thumbnail /absolute/specimen.six` requests an undecorated 16x12 scale-1 thumbnail through `QLThumbnailGenerator`; `sixel-quicklook-render preview /absolute/specimen.six /absolute/new-output-directory` runs `/usr/bin/qlmanage -p -o` without a preview window. Use the exact hand-authored [specimen](../../tests/extension/quicklook-render/specimen.six), an opaque 16x12 image with eight red columns followed by eight blue columns. No encoder or extension decoder generates the expected pixels. The probe rejects other input bytes. The preview directory must not already exist and its parent must exist. Retain the output and stderr as evidence; removal is the operator's responsibility.

The thumbnail representation must be a final thumbnail, not an icon or low-quality substitute. Preview accepts exactly one PNG within the output tree (at most 128 entries); HTML, PDF, missing or ambiguous image output is unsupported evidence and fails rather than falling back to thumbnail generation. ImageIO and an sRGB bitmap context check exact dimensions and all opaque red/blue endpoint samples. No scaling or perceptual tolerance hides a mismatch. The 10-second generation deadline reports status 124; preview timeout kills and reaps the direct `qlmanage` child, but does not control the lifetime of an OS Quick Look service. The complete process, API/IPC wait, output inspection and comparison belong in the caller's normal measured interval. No cache reset, service restart, registration, election, handler change or user impersonation is performed. Generation itself may populate OS caches and therefore is not part of read-only installcheck.

These public interfaces do **not** expose a selected provider path, code identity or cache provenance. `QLThumbnailGenerationRequest` explicitly permits cached final thumbnails; a fresh output directory does not bypass that cache. A `qlmanage -g` generator override is not evidence that the current app extension was selected. The QuickLookUI preview view/panel interfaces expose a preview item and UI, not an attributable headless rendered-image callback. Installed path/signature and user/session observations from [installcheck](#installed-observer-input-contract) remain separate prerequisites, not a causal link to a render result. Do not use private API or a process name, exit status, handler string or matching pixels to fill that gap.

JSON output records `commandStatus`, `imageMatches`, `providerVerified: false` and `cacheProvenance: "unavailable"`. A live image match exits **2**, explicitly incomplete provider evidence; command failure/timeout is preserved, image mismatch exits 1 and invalid arguments/input exit 64. A live exit 0 is never manufactured. Exact provider execution and cache origin remain unverified even after content agreement. Actual system deployment, activation/restoration and Finder/GUI evidence require a separately approved environment.

`check-preview DIRECTORY` and `check-thumbnail PNG` exercise only the output readers against private images, emitting `offline: true` and returning 0 for matching content or 1 for rejection. The normal tests exercise these two readers with literal PNG references and targeted changed-color/dimension negatives. They do not call Quick Look or establish actual provider execution. Their PNGs are independent literal RGB samples with an sRGB chunk; they are not SIXEL roundtrips. Disabled or cross configurations skip for their stated capability reason; those skips are not rendering successes.

### Coverage boundary

The [companion-program inventory](../testing/companion-programs-coverage.md) lists these build observations. They verify assembly, development package metadata, publication/expansion correspondence, payload identity and ad hoc signature validity. Read-only native observations parse actual Mach-O headers and all supported thin or universal slices, including dylib, dynamic-loader and rpath load commands and deployment requirements; they do not reuse the producer's lipo/otool results. Each identity, UTType, numeric-version and executable observation names one bundle. Each architecture and dependency observation opens one code subject, including a separate result for each helper. A failure in one subject does not suppress results for the others. Provider declarations and extension entitlements also have individual subjects. Package-wide relationships remain single observations: publication correspondence, the deployment maximum across all code and bundle declarations, the Distribution/manifest architecture declaration, and complete component-policy identifier sets. They do not test installation, release signing/notarization, registration lifecycle, default handlers, preview UI or thumbnails. The [Quick Look loader suite](../../tests/loader/quicklook/) tests input preview acquisition and must not be counted as testing the distributed extension. Architecture and minimum deployment versions must be inspected in the actual Mach-O outputs; SDK availability and plist declarations alone do not prove execution on older macOS versions.

## Explicit user operations and lifecycle

The common [user entry](../../tools/quicklook-user.sh) requires an already-built distribution and explicit JSON inputs. `register-quicklook-extension`, `set-default-quicklook-extension`, and `deactivate-quicklook-extension` dispatch separate operations; ordinary install and installcheck never dispatch them. Set `QUICKLOOK_USER_REQUEST` to a JSON file containing numeric `uid` and `session`, and `QUICKLOOK_USER_JOURNAL` to an existing canonical directory owned by that user with mode 0700. Run inside that user's matching local console GUI session. No root impersonation, environment-based user discovery, elevation or password dialog is synthesized. `QUICKLOOK_DRY_RUN=yes` prints argv without executing it; staging variables reject user operations.

The native journal writer uses an exclusive directory lock, no-follow relative file descriptors, a mode-0600 temporary file, fsync and atomic rename. It persists intent before dispatch and fresh observations afterward. Interrupted writes and pending operations are retained for operator review. Registering the two apps uses public Launch Services; absent providers are added by exact installed path. Existing elections are preserved. Activation does not call a default setter. A successfully registered but ignored provider is not proof of rendering availability.

The independent default request additionally requires `extensions: ["six", "sixel"]` and `restoreDefault` containing the exact, complete current default identity. Both extensions must resolve to the dedicated SIXEL UTI and the same uniquely restorable application. Missing, shared, ambiguous or changed identities refuse mutation. Supplying this request explicitly selects that application as the later restoration target; the public getter cannot prove whether it was previously an explicit choice or an effective fallback. macOS 12 and newer use the asynchronous NSWorkspace setter, wait for its completion including consent, and re-read the effective default. The older Launch Services fallback is source-supported but requires separate runtime validation. Neither path silently dismisses consent or converts cancellation into success.

Deactivation restores a changed default only while both current extension records still equal the owned value and the original application remains unique with its recorded signature. Later user choices remain untouched. Only providers added by this journal are removed, and their current complete records must still match. Unknown outcomes remain pending rather than becoming an automatic rollback. Original operation status and journal cleanup failure are reported separately. Public Launch Services has no equivalent database-restoration operation here: app registrations may remain as stale rows until owned payload removal and OS convergence. No private database rewrite, global cache clear or service termination occurs.

The journal retains the accepted read-only `before`/`owned` context fields and adds events, current observations and restoration state. `current == owned` is not proof of `before == current`, provenance or complete rollback. `remove-quicklook-users` requires `QUICKLOOK_PARTICIPANTS`, a version-1 JSON object with a nonempty `participants` array of explicit numeric `uid` and canonical `journal` file paths. It validates private file ownership, exact distribution identity and completed deactivation records before system removal. The administrator owns the completeness and freshness of this list; records cannot attest to unlisted users or later external changes. The older system-only declaration flag alone is not user restoration evidence.

`archive-quicklook-copy`, `remove-quicklook-copy` and `restore-quicklook-copy` are separate explicit legacy-copy operations. Their request additionally names `component` (`host` or `bridge`) and an exact canonical `path`, and the distribution must describe those original bytes. Normal activation rejects old-copy conflicts. Archive preparation verifies full inventory, modes, signature, user ownership and extended attributes, refuses a running copy, and preserves a resource-aware ZIP outside an app directory. Removal rechecks ownership and does not recursively delete unexpected children. Restoration validates the archive and uses an exclusive rename into the original empty path; occupied paths and cross-volume renames are refused with evidence retained. Copy restoration and registration do not establish original default/election restoration or instant disappearance of stale LS rows. Unknown or unprovable copies are never automatically adopted. The owned journal preserves the top-level app attributes that the ZIP representation can omit. Archive preparation extracts into a new private workspace, reapplies that root sidecar, and verifies the complete inventory, modes, attributes and signature before marking the archive verified. Removal requires that verified record and unchanged source/archive identities. Restoration repeats extraction and verification before publishing. A failed round trip retains the original copy and incomplete evidence; it does not authorize deletion.

`check-quicklook-installation` uses the same native sequential lifecycle runner in both builds. `QUICKLOOK_LIFECYCLE_PLAN` names a version-1 JSON object with `explicitLifecycle: true` and argv arrays `check`, `install`, `activate`, `observe`, `deactivate`, `remove`, `restore`, and `verify-restored`; `set-default` is optional and separate. Every executor must have an absolute path and is an explicit operator trust boundary. The operator supplies already authorized system and GUI-user executors, an original distribution and restoration commands appropriate to the environment. No executor is inferred or elevated. `QUICKLOOK_LIFECYCLE_RECORD` names a new private mode-0700 run directory. Stages execute serially even under an outer parallel build. Failure stops forward progress; failed deactivation prevents system removal, and an unknown Installer outcome is retained for recovery. The original failure and cleanup status remain separate. A known command failure is held before completion-event persistence and remains the process exit status if that persistence fails. Recording failure immediately stops subsequent mutation; stderr reports `originalStatus`, nullable `cleanupStatus`, `cleanupState` and `recordingFailure` separately. This diagnostic is not durable journal evidence: the last published journal may still show a pending intent. `cleanupState` distinguishes `not-attempted`, `completed`, `failed` and (in failure diagnostics) `interrupted`; unattempted cleanup has a null status and does not establish restoration. If no command failed, recording failure returns status 1. A successful supplied command is only evidence for the behavior that command actually verifies; private executor success is not actual Installer or GUI proof.

Legacy record/path observations are separate from independent restored type, byte, mode, extended-attribute and signature comparisons. The original copy snapshot is captured before removal; the signature expectation comes from the original distribution manifest. Each observation reads and validates its required current state inside the measured native process. Private guard preparation captures before/after payload inventories, receipt content and lock presence around each competing command because those transient windows cannot be queried after the Installer returns. Numbered observations distinguish every action/window refusal from the lock, each owned root and receipt invariants. Standalone removal observes Host, Bridge, support and receipt absence separately instead of inferring all payload absence from Host alone. These copy checks do not prove default/provider migration.

An activation retry is read-only when all current values still equal the recorded owned values. A changed current value refuses activation without registering, adding providers or replacing the original before/owned evidence. Deactivation preserves a later default choice using the original record; a changed provider record blocks removal and requires explicit review. A completed deactivation retry leaves its original restoration evidence unchanged.

The explicit no-setter migration entry supports known archived copies whose bundle ID is also the original SIXEL handler. Ordinary activation retains its duplicate checks. The migration request contains numeric `uid` and `session` and a `legacy` array of one or two objects, each naming an original `distribution` directory, the legacy `request` JSON path and its private `journal` directory. Archive all participating old copies before removing any of them so their original user observations agree. The archive must have passed extraction verification. The original default and any original providers must belong to those exact archived instances. Unknown copies, altered archives, occupied original paths and session mismatches refuse the operation.

Both builds expose `migration-activate-quicklook`, `migration-prepare-quicklook`, `migration-restore-quicklook` and `migration-verify-quicklook` through `QUICKLOOK_USER_REQUEST` and `QUICKLOOK_USER_JOURNAL`. Their native equivalent is `sixel-quicklook-package migration ACTION DISTRIBUTION REQUEST JOURNAL`. After explicit old-copy removal and system installation, `activate` binds old/new distribution hashes, archive hashes, original identities and UID/session to the user journal. Only exact archived paths proven absent can be treated as stale rows; live third-party instances remain conflicts. This entry never calls a default setter. Its activation observations do not acquire permission to overwrite a later choice.

`prepare` requires unchanged owned current values, removes only providers created by activation, and publishes `removal-ready`, which is explicitly not restored or deactivated. Root removal uses the existing `remove-quicklook-users` entry: each migration participant additionally supplies `migration: true`, numeric `session`, and `journalSHA256` for that exact ready record. Root validates the private owned journal and new distribution identity before its ordinary guarded payload/receipt removal; it does not execute user commands or impersonate the GUI session. The administrator must provide a complete, fresh participant list. A digest binds a record, not a cryptographic assertion of consent or an atomic lock on external OS choices.

After all system roots and the exact receipt are absent, `restore` rechecks the user session and default/provider boundary, verifies archives and original empty paths, restores/registers those exact old copies and observes provider registration. A different handler, unexpected live choice or later provider record stops this sequence. It never forces an election or sets a default. `verify` independently requires each restored copy identity, absence of system payload/receipt, unambiguous LS instances, original provider path/version/election, and each extension's complete original resolved default identity. A fresh provider UUID may differ after registration and is retained as current evidence. Only then is the journal `observed-restored-no-setter`; a matching handler string alone is insufficient.

Registration need not make the original default resolve again. An unresolved or ambiguous observation returns nonzero and remains pending. This narrow protocol does not restore private OS databases, prove prior explicit-choice provenance, guarantee convergence, resume arbitrary interrupted stages, or supply an additional restoration-choice setter/UI. Partial failure retains archives and pending journals for explicit recovery; it is not automatic rollback. An external choice can race a public API observation because these APIs provide no compare-and-swap transaction. Real OS restoration and provider/GUI success require separate managed-environment validation. The existing explicit lifecycle plan can use migration `prepare` as its `deactivate` command, participant removal as `remove`, and the two user phases as `restore`/`verify-restored`, with separate operator-supplied system and GUI executors.

Raw OSStatus/NSError causes are retained in journal diagnostics. Because a process exit has only eight status bits, a nonzero API code whose low byte is zero is returned as exit 1; ordinary external command statuses retain their existing value.
