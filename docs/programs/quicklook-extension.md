# SIXEL Quick Look extension

The macOS extension lets Quick Look preview and thumbnail providers decode `.six` and `.sixel` files for Finder and other Quick Look clients. It is an optional companion program, disabled by default. The [Quick Look input loader](../loader/quicklook.md) instead asks installed providers for a preview to feed into `img2sixel`; enabling that loader does not install this extension.

## Components and requirements

The implementation in [quicklook-extension](../../quicklook-extension/) targets macOS 10.15 or newer with an Objective-C compiler and the Apple QuickLook, QuickLookThumbnailing, Cocoa, CoreGraphics and related system frameworks. The deployment target in the compiled Mach-O is determined by the selected compiler/SDK flags and can be newer than the plist minimum; choose and inspect that target before distribution. Configuration checks the available APIs; the broader [platform matrix](../platform-support.md) does not imply that every extension deployment path is exercised.

`SixelQuickLookHost.app` contains `SixelPreview.appex` and `SixelThumbnail.appex`. `SixelPreviewBridge.app` provides the file-opening bridge, and `register_sixel_preview` sets Launch Services handlers. The bundles declare the `com.saitoha.libsixel.sixel` type for `.six` and `.sixel`. Their SIXEL decoding core is compiled into `libsixelquicklookcore.a` and linked into the providers and bridge, with external image libraries disabled; they still depend on macOS frameworks. The archive is a build artifact, not a separate runtime dependency.

## Autotools build and installation

From a configured source/build tree on macOS:

```sh
./configure --enable-quicklook-extension
make
make install
```

The option defaults to `no` in [configure.ac](../../configure.ac), independently of `--enable-quicklook-preview`. [quicklook-extension/Makefile.am](../../quicklook-extension/Makefile.am) assembles both apps under `quicklook-extension/products/` and produces `quicklook-extension/package/SixelQuickLook.pkg` during the normal build.

The extension part of `make install` invokes the common [package management wrapper](../../tools/quicklook-extension.bash), which calls `/usr/sbin/installer -pkg <finished-package> -target /`. The native helper validates the published package and manifest hashes first. It never copies apps directly, signs installed code, runs user registration, chooses a user from environment variables, changes a default handler or resets caches/services. Installer itself may cause OS discovery of installed apps; system installation does not claim that a user has activated the providers. Insufficient privileges return status 77 with an administrator command, without invoking sudo or a password dialog. Installer's nonzero status is returned unchanged by the helper; build runners may report their own enclosing failure status.

The explicit `install-quicklook-extension` target uses that same operation. `installcheck-quicklook` and the extension's Automake `installcheck-local` only observe the expected manifest, installed payload and exact receipt. They do not build, install or repair anything. Missing installation or a pending/unreadable operation lock fails; nonempty DESTDIR (or `SIXEL_INSTALLCHECK_DESTDIR` for observation only) prints an explicit STAGING skip, which is not evidence of system installation. These checks do not establish GUI activation or rendering.

### Distribution staging and dry-run

With a nonempty `DESTDIR`, installation only stages `SixelQuickLook.pkg`, `payload-manifest.json`, `package-evidence.json` and the native management tool at `${DESTDIR}${datadir}/libsixel/installers/`. A `.quicklook-stage.json` records those owned distribution files. No system payload is expanded, Installer or receipt command is run, or user registration/default/cache/service is changed. Staging mutations require absolute DESTDIR and datadir paths without `..`; internal spaces are preserved, empty DESTDIR selects system installation, and the wrapper rejects a whitespace-only relative staging destination. GNU Make can trim a whitespace-only command-line variable assignment to an empty value: use an absolute staging path. Read-only installcheck skips for any nonempty staging variable without accessing that path. Symlinked destination ancestors are refused, including `/tmp`; use its canonical `/private/tmp` path on macOS.

DESTDIR uninstall checks the complete staged inventory and hashes, removes only matching files and the empty installers directory, and retains shared parents. Changed, extra, missing or symlinked stage contents are refused before deletion. A failed stage write can leave an incomplete distribution requiring operator inspection; it is not silently adopted or recursively erased on retry. `make -n install`, Meson `install --dry-run`, and the wrapper's `--dry-run` do not perform OS installation. The wrapper dry-run returns before executing even the native helper.

### Ownership, exclusion and removal

The [native management implementation](../../quicklook-extension/Sources/SixelInstall.h) shares the package's manifest and receipt checks. Managed install and uninstall atomically acquire `/private/var/run/libsixel-quicklook-managed.lock` as an outer operation guard. Managed install holds it before invoking Installer until its child exits successfully and the exact receipt and installed payload pass final validation. Managed uninstall holds the same guard through removal and receipt absence verification. Concurrent managed calls fail immediately with `wait=0`, including the interval between postinstall, receipt commit and the final check. Read-only installcheck refuses either pending guard or package lock.

Package preinstall independently acquires `/private/var/run/libsixel-quicklook.lock` before preflight. Postinstall verifies installed bytes/attributes and releases only that package lock. A normal standalone Installer.app or `/usr/sbin/installer` installation therefore requires no additional completion command and leaves no project lock after successful completion. Package scripts do not release or adopt a managed caller's outer guard. A standalone Installer has no outer guard: concurrent managed administration after its postinstall and before its receipt commit is outside this exclusion guarantee. Run standalone Installer and managed operations separately. This limitation does not apply to concurrent managed install/uninstall calls, which remain excluded until their caller's final checks finish.

There is no timeout-based or PID-based stale-lock deletion. A package preflight failure releases only its package lock. A managed install child failure, exception or final validation failure retains its outer guard for operator inspection, even if no package lock remains; a nonzero child status does not prove that no mutation occurred. Managed uninstall precondition failures release their own acquired locks, while failures after deletion starts retain recovery evidence. Original Installer/receipt failure status is preserved. Package interruption before successful postinstall can leave its package lock; standalone failure after postinstall may leave an inconsistent receipt/payload without a project lock and requires explicit inspection. Never treat absence of a lock as installation success. No helper provides a transaction covering unrelated macOS Installer activity.

`make uninstall` delegates the extension portion to `uninstall-quicklook-extension`. System removal requires root, the exact expected distribution manifest and receipt, complete unchanged owned trees, and an explicit declaration that all affected users have already restored their settings: set `QUICKLOOK_USERS_DEACTIVATED=yes` for the explicit target, or pass `--users-deactivated` to the wrapper. This declaration is an administrator prerequisite, not automatic proof of user deactivation. No user is inferred or edited. Absent receipt and absent destinations are idempotent; residual unowned files, unexpected children, changed payload, or a different expected distribution fail. Only manifest-owned files and empty owned directories are removed, with `unlink`/`rmdir`, followed by `pkgutil --forget` for the exact receipt and an absence query. Shared parents and `~/Applications` are never deleted. Failure after deletion starts leaves receipt/lock evidence for recovery; no recursive cleanup or repair is attempted.

Before system work, preserve the original distribution package, payload/receipt evidence, shared parent attributes and each participating user's registration/default state in a managed environment. After a failure, stop competing operations, inspect the remaining payload/receipt and lock identity, and arrange explicit restoration or removal. Never blindly remove a lock to force a retry. Automatic repair, adoption of old per-user copies, migration, user activation/default restoration and a complete lifecycle orchestrator are not implemented. Perform any user actions separately and explicitly; the legacy `--products-dir`/`--user-home` copy/delete interface is rejected. Real Installer transitions and restoration must be validated independently of private fixture tests.

## Meson build boundary

The corresponding opt-in is:

```sh
meson setup builddir -Dquicklook_extension=enabled
meson compile -C builddir
```

`quicklook_extension` defaults to `disabled` in [meson_options.txt](../../meson_options.txt), independently of `quicklook_preview`. [quicklook-extension/meson.build](../../quicklook-extension/meson.build) builds the standalone decoder archive, four executables, registration helper and generated plists. The [bundle producer](../../quicklook-extension/products/meson.build) assembles both app trees under the build directory's `quicklook-extension/products/` during a normal build. `meson compile -C builddir quicklook-extension-bundles` selects that producer and the registration helper explicitly. Each copied executable and plist is a dependency, so clean out-of-tree and parallel builds do not rely on source-tree products.

Both build systems use [assemble-bundles.sh](../../quicklook-extension/assemble-bundles.sh) to copy completed native executables and plists into fresh bundle trees. Assembly does not sign or register the apps; any later signing must consume these completed outputs after binary modification. The extension cannot be combined with the executable shebang-prefix option: prepending a script header does not preserve a native Mach-O bundle executable. A changed executable, generated plist or assembly script invalidates the producer. Deleting files inside an otherwise unchanged generated directory requires rebuilding the bundles from a clean output; directory timestamps alone are not an integrity check.

`meson install -C builddir` calls the same wrapper with the same finished package, privilege and DESTDIR contracts. It does not install app trees or the registration helper separately. The explicit `install-quicklook-extension`, `uninstall-quicklook-extension` and read-only `installcheck-quicklook` run targets select the corresponding operations. The generic `installcheck` run target also observes the extension before checking installed CLI programs. Meson's standard `uninstall` does not invoke custom install scripts and therefore does not remove the system package or custom staged distribution: use `meson compile -C builddir uninstall-quicklook-extension` with the same DESTDIR when staging, or the documented user-deactivation prerequisite for system removal. This limitation is not reported as successful package removal. Build-system dry-run semantics follow [Meson's install-script contract](https://mesonbuild.com/Reference-manual_builtin_meson.html#mesonadd_install_script).

## Installer package construction

When the extension is enabled, both normal builds run the native [package tool](../../quicklook-extension/Sources/SixelPackageTool.m) after assembly. `pkgbuild`, `productbuild`, `pkgutil`, `lsbom`, `codesign`, and Xcode CLT's `lipo` and `otool` are required; the shared [prerequisite check](../../quicklook-extension/check-package-tools.sh) reports missing tools during configuration. No third-party Installer authoring software, Python runtime, release certificate or root privileges are required. Disabled configurations do not perform these package tool checks or generate a package. Reconfiguring an enabled directory to disabled can retain old artifacts; absence must be observed in a separately prepared fresh build.

Use `--with-quicklook-package-version=1.0.0` with configure or `-Dquicklook_package_version=1.0.0` with Meson to set the distribution build number; both default to `1.0.0`. The accepted form is three canonical decimal integers, with major 1–9999 and minor/patch 0–99. Raise this number for every changed distribution payload, including a different architecture. The four final `CFBundleVersion` values and component package version use this number. `CFBundleShortVersionString` uses the validated numeric release portion of the upstream version; the complete upstream string remains in the manifest as source provenance. A timestamp or dirty Git state never silently assigns a distribution number.

The package contains these fixed system-relative trees, under one receipt identifier `com.saitoha.libsixel.quicklook.pkg`:

- `/Applications/SixelQuickLookHost.app`, including Preview and Thumbnail extensions;
- `/Applications/SixelPreviewBridge.app`;
- `/Library/Application Support/libsixel/QuickLook/`, containing `payload-manifest.json`, the native package/preflight tool, and `register_sixel_preview` (not executed during construction or preflight).

The producer copies the assembly outputs into its private `package/work/root` before changing distribution plists and signing. The original `products/` executables and generated plists retain their assembly identity, so their byte-comparison tests remain applicable. Every packaged executable is inspected across its Mach-O slices: architecture sets must match, only macOS load commands are accepted, and runtime dylib/rpath references outside `/usr/lib/` and `/System/Library/` are rejected, including private build prefixes and sanitizer runtimes. Supported architecture names are `arm64` and `x86_64`; execution on untested architectures is not established by packaging. The highest actual minimum OS across all packaged code, with a floor of 10.15, becomes every final bundle's `LSMinimumSystemVersion` and the product's allowed OS minimum. The product also declares the actual architecture set and system-only Installer domain. These declarations describe binary requirements; they do not establish runtime compatibility on older systems.

Signing proceeds from inner Preview/Thumbnail extensions to Host, then Bridge and the auxiliary executables. Each signing invocation runs in a dedicated `/bin/sh` child that sets umask 022 and immediately executes `codesign`, with arguments passed separately from the fixed shell command. The parent never changes its mask, so restoration is unnecessary even on failure and unrelated packaging operations keep the caller's mask. All four `Contents/_CodeSignature/CodeResources` files must be regular files with mode 0644 before manifest creation and archiving; their modes are never repaired after signing. The extension signatures use the declared [sandbox entitlements](../../quicklook-extension/Resources/QuickLookExtension.entitlements). The builder verifies code signatures before writing a manifest of fixed relative paths, kinds, modes, SHA-256 file hashes, bundle identity/version, architecture, minimum OS and signature identifiers/CDHashes. Symbolic links and unsupported file types are rejected, including symlinked destination ancestors during preflight. Payload verification enumerates the actual trees, uses `lstat` for numeric type/mode/ownership without following links, and hashes every regular payload file. Missing ancestors are allowed for a new destination; other ancestor stat errors are refused. The full inventory and comparison execute inside each observation; no prior successful result is cached. The manifest excludes its own hash. Its private staging file is explicitly set to mode 0644 before copying into package scripts or archiving, independent of the caller's umask; existing assembly files and signed code are not chmodded. The Bom inspection requires this fixed manifest mode. `package-evidence.json` records the external manifest and package hashes, plus a format-2 inventory of every expanded path, node type, mode and regular-file SHA-256 (including Distribution, PackageInfo, Bom, Scripts and Payload). Signed payload is never modified afterward.

Both builds currently produce **ad hoc signed code inside an unsigned development package**. This is not Developer ID distribution, notarization or Gatekeeper approval. Release distribution needs a separate qualified signing pipeline using Developer ID Application for code, Developer ID Installer for the final package, and notarization. Changing signatures changes payload identity: regenerate the manifest and package after code signing, and do not mutate the signed bundle afterward. Certificate acquisition, notarization submission and release publication are not implemented by this producer. Apple's [packaging guidance](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution) distinguishes these code and container signatures.

`pkgbuild` receives explicit non-relocatable, strict-identifier, version-checked, whole-bundle `upgrade` component policies for all four bundles. `productbuild` creates the distribution archive with explicit domains, OS and architecture requirements, following Apple's [Distribution XML reference](https://developer.apple.com/library/archive/documentation/DeveloperTools/Reference/DistributionDefinitionRef/Chapters/Distribution_XML_Ref.html). The builder expands the actual package with `pkgutil --expand-full`, verifies its payload and manifest identity, checks the resulting PackageInfo/Distribution and final signatures, then publishes the package last. The expanded archive under `package/work/expanded` is a declared shared build artifact for read-only observations; expansion is not performed inside each test. The publication correspondence observation reads and hashes the current public archive and manifest, enumerates and hashes the full expansion, and compares all three with the same evidence record. Missing or replaced archives, changed evidence or manifests, stale expansions, and altered metadata/scripts fail this observation without rebuilding or repairing anything. Evidence binds the producer's completed expansion to the archived bytes; it is local provenance, not a cryptographic attestation against deliberate replacement of the whole package/evidence set. A build may regenerate missing outputs; use `meson test --no-rebuild` or already-built Autotools test log targets when testing rejection of an existing mismatch. Removing an internal output requires an explicit package rebuild for repair.

The package explicitly sets `overwrite-permissions="false"` in the component `PackageInfo`. Shared parent records in the Bom describe defaults for newly created directories; they must not replace the owner, group or mode of existing `/`, `/Applications`, `/Library`, `/Library/Application Support` or `/Library/Application Support/libsixel`. The builder uses `pkgutil --expand` (without expanding Payload), edits only this metadata attribute, and uses `pkgutil --flatten` before `productbuild`. Signed payload bytes and the original Bom remain unchanged. The expanded real archive must declare this preservation policy, and its Bom must contain only the expected payload and shared parent records, with root:wheel ownership and the declared file types/modes. Manifest validation independently requires each of the four signature resources at mode 0644, so matching manifest and Bom entries at 0600 cannot satisfy the distribution contract. Optional AppleDouble records must correspond to an expected path with matching attributes. Owned directories use mode 0755. Existing owned trees must match their recorded payload; real system preflight also refuses owned directories with a different owner/group, rather than using permission repair scripts. A package that would require changing retained owned directory attributes is not an automatic upgrade.

Apple's [Software Distribution Legacy Guide, File Permissions](https://leopard-adc.pepas.com/documentation/DeveloperTools/Conceptual/SoftwareDistribution4/SoftwareDistribution4.pdf#page=79) describes preserving existing directory permissions when overwriting is disabled. This is historical authoring guidance, not proof of modern Installer execution. Verification here inspects the actual PackageInfo/Bom and signed payload. Successful signature verification as the extraction owner does not establish readability by an installed ordinary user; the fixed resource mode is a separate distribution requirement. Actual installed-user signature verification and launch remain untested here; a managed installation test must still compare shared parent owner/group/mode before and after installation and upgrade, including deliberately customized parent attributes.

The embedded [preinstall script](../../quicklook-extension/package-preinstall) acquires the operation lock and invokes the same native tool's read-only state check. It refuses non-system target volumes, unowned occupied destinations, receipt/manifest version or location disagreement, changed/missing/extra owned payload files, downgrades, and same-version distributions with a different manifest. Identical-payload reinstallation and higher-version payloads require the current owned trees to match their recorded manifest; automatic repair and adoption of existing copies are unsupported. Shared parent directories are not owned. The state check does not modify user registrations, defaults or caches; only its operation lock is created by the script wrapper. The pure state checker supports private fixture roots for regression tests, while the Installer entry fixes the root at `/` and reads the exact receipt with `pkgutil`.

Package generation and archive inspection do not run Installer or launch the applications. The install integration above is separate from package construction. Metadata and private-root checks do not establish actual installation, upgrade/downgrade refusal, rollback, ordinary-user signature verification, shared-parent preservation or user activation on the machine. Full installed-state and lifecycle verification remain separate from the focused read-only manifest/receipt check.

## Use and validation boundary

After installation, select a SIXEL file in Finder and request Quick Look (Space), then inspect its thumbnail separately. Opening a file uses the bridge and handler association. Quick Look caches, provider enablement, signing and the active user session can affect these observations; log out and back in when checking a changed registration. Verify both the installed paths and rendered content before claiming successful deployment.

### Coverage boundary

The [companion-program inventory](../testing/companion-programs-coverage.md) lists these build observations. They verify assembly, development package metadata, publication/expansion correspondence, payload identity and ad hoc signature validity. Read-only native observations parse actual Mach-O headers and all supported thin or universal slices, including dylib, dynamic-loader and rpath load commands and deployment requirements; they do not reuse the producer's lipo/otool results. Each identity, UTType, numeric-version and executable observation names one bundle. Each architecture and dependency observation opens one code subject, including a separate result for each helper. A failure in one subject does not suppress results for the others. Provider declarations and extension entitlements also have individual subjects. Package-wide relationships remain single observations: publication correspondence, the deployment maximum across all code and bundle declarations, the Distribution/manifest architecture declaration, and complete component-policy identifier sets. They do not test installation, release signing/notarization, registration lifecycle, default handlers, preview UI or thumbnails. The [Quick Look loader suite](../../tests/loader/quicklook/) tests input preview acquisition and must not be counted as testing the distributed extension. Architecture and minimum deployment versions must be inspected in the actual Mach-O outputs; SDK availability and plist declarations alone do not prove execution on older macOS versions.
