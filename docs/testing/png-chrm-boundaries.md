# libpng cHRM Integer-Grid Boundary Tests

The [PNG metadata policy](../loader/png-color-metadata.md#libpng-integer-grid-boundary-contracts) owns the accepted source behavior. This inventory records every focused boundary test, including defensive observations that do not independently define public contracts. The [libpng loader](../loader/libpng.md) owns component selection and frame delivery.

## Fixtures and independent expectations

[`generate_png_chrm_fixtures.py`](../../tools/generate_png_chrm_fixtures.py), called by [`generate_color_fixtures.py`](../../tools/generate_color_fixtures.py), generates 236 eight-pixel PNGs and the embedded C/JSON oracles from original integer coordinates, original 8/16-bit samples, and the independently generated palette ICC seed. It uses 100-digit Decimal Gaussian elimination, transfer evaluation, and file-background composition; it does not call a libsixel evaluator or derive expectations from observed product output. Run `python3 tools/generate_color_fixtures.py --check` to detect fixture or oracle drift.

The D65 matrix probes vary the red primary through inside, zero, and outside Z and rotate that boundary through green and blue. RGB, RGBA, and file-bKGD images retain original samples, partial alpha, zero-alpha hidden RGB, and extended linear values. Gamma-only, untagged, rejected ICC, ICC/cHRM, sRGB/cHRM, ICC/sRGB, and triple coexistence controls keep source priority observable. Invalid coordinates, singular matrices, malformed length/CRC, and signed-range values exercise fallback. No new non-D65 or APNG accuracy contract is asserted here.

The exact-singular additions hold two distinct collinear primary triples across D65, D50, and a near-zero Bradford-cone white, both depths, both transfer choices, RGB/RGBA/file background, and all primary permutations. Their fallback expectations use the surviving transfer metadata and original samples; they do not construct a nonexistent source matrix. Rational Gaussian elimination of homogeneous integer XYZ columns independently verifies singularity. Additional conflicting-metadata and disabled-CMS controls preserve precedence. The JSON inventory separates the originating fixture, IDAT equality, and whole-PNG equality; shared raster bytes do not imply identical PNG metadata.

## Observation mechanisms and budgets

The grid tests include the exact private production helper [`loader-libpng-chrm.h`](../../src/loader-libpng-chrm.h). One roundtrip observation checks every usable zero-Z pair for both floating scale expressions (200000 cases). Separate invocations compare exact X/Y/Z for white/red/green/blue zero and adjacent inside points, and reject outside or unsafe floating values before an integer cast. These tests run even when libpng is disabled. The separate private [`loader-libpng-chrm-area.h`](../../src/loader-libpng-chrm-area.h) is called for both floating scale expressions and compared with literal signed areas from independent homogeneous determinant elimination: twelve collinear permutations, area +/-1, and area +/-9,999,800,001. The latter requires more than 32-bit intermediate arithmetic.

Four valid-primary component fixtures separately assert that cHRM-only opaque RGB selects a linear float frame, including black, finite output, and one callback. Rejection would instead deliver encoded RGB, making sign-only or magnitude-one rejection observable without asserting unresolved close-primary numerical accuracy. The acceptance entry uses a distinct marker and never claims that its three black components are a 24-component accuracy test. CMS-disabled controls still compare all original samples.

The sample entry constructs the libpng component directly, verifies its identity, and decodes an embedded PNG; it cannot silently fall back to another loader. Every invocation checks one eight-pixel frame, all 24 RGB components, storage and colorspace, alpha/mask coverage, and exactly one callback. Unconverted bytes and gamma float32 normalization are exact. Direct linear expectations use a fixed `2e-7` absolute component budget. The separate ColorSync ICC controls use `0.000324`; they cannot relax a direct cHRM assertion. Transfer output may still pass through float32 before the matrix; these tests compare with an independent ideal result within the direct budget.

External getter probes inspect the linked libpng independently of the adapter. For malformed metadata the numeric oracle chooses among precomputed source interpretations using those getters, because libpng versions may withhold gAMA together with rejected cHRM. This selection never uses a product numeric result. Three explicit getter-rejection tests prevent malformed cHRM from silently becoming an accepted matrix. The fallback tests still compare original samples with an independent gamma/sRGB result.

Each numeric TAP file invokes one C observation in a fresh process and requires its exact completion marker. ICC controls consume every apply in order: one for an image, two for an image with file background, and zero for direct metadata or disabled CMS. Every record must match the requested engine, expected backend path, float source/destination formats, and success field exactly, with no extra record or payload. Missing libpng or a CMS backend absent from the build returns `1..0 # SKIP`; a compiled engine resolving to another engine is a diagnostic failure. The grid entries have no unavailable-feature skip. The builtin CMS numeric matrix covers the original 126 fixtures and 106 exact-collinear/fallback/priority additions; disabled-CMS and optional lcms2/ColorSync controls cover the selected cross-engine observations without duplicating every malformed variant.

Mutation validation should run these same entries and TAP wrappers with altered private builds: reject zero, accept the adjacent outside point, drop nearest rounding, compute Z by floating subtraction, weaken negative-coordinate checks, remove the exact area guard, replace its zero test with a sign-only or magnitude-one rejection, narrow its integer intermediates to 32 bits, and skip either image or background matrix application. A failing numeric entry and `not ok` TAP result establish detection; an altered binary name or trace alone does not.

The trace-only controls call the actual numeric TAP wrappers through a small C fixture; they do not decode PNGs or claim numeric coverage. Two valid controls protect acceptance of one/two correct records. Separate negative controls replace only the background engine/path/source/destination/status, remove or rename its apply, add an extra field or apply, inject apply into direct/disabled-CMS cases, and return status 77 to a grid wrapper. Each compares the nested TAP stdout exactly; the controlled child stderr and temporary shell tracing are suppressed so intentional negative TAP text cannot contaminate the outer harness stream or satisfy its assertion. The child fixture restores the existing harness-provided library path after a system-shell boundary on macOS. Private mutation validation additionally replaces the actual compiled engine selection and the actual background backend, and removes or renames background apply events while running these permanent numeric TAPs.
