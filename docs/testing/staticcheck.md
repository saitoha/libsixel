# Staticcheck: Repository Invariant Verification

## Role in libsixel development

`staticcheck` is the libsixel name for the repository-wide invariant-verification target. The term is project-specific: it must not be confused with a particular third-party linter or with the narrower idea of checking one source file without executing it. Linters are one input to `staticcheck`, but they are not its boundary.

As the codebase grows and the test inventory has reached roughly 5,000 cases, successful execution of those tests is not enough to preserve quality. A test can pass while its registration is missing from another build system, a generated header is stale, a CLI option has disappeared from a manual, a binding constant no longer matches the C API, or the test itself violates the repository's one-observation rules. `staticcheck` is the quality control layer that makes those forms of drift fail explicitly. It is therefore a maintenance lifeline for the codebase and test suite, not optional cosmetic lint.

The umbrella target accepts any deterministic check of the repository's static contract. In this context, “static” means that the observation concerns source, metadata, generated or configured artifacts, build structure, interface inventories, or the structure of tests rather than the result quality of a normal image-processing scenario. A check may parse C with an AST, regenerate a file into a temporary location, compile a warning probe, inspect symbols, or execute a built program's `-H` introspection path. The implementation technique does not determine the category; the invariant being checked does.

## Scope

The target deliberately spans more than conventional lint:

| Check family | What it protects | Representative mechanism |
| --- | --- | --- |
| External lint and syntax | Shell, workflow, spelling, and language syntax accepted by maintained tools. | ShellCheck, actionlint, codespell, and Python compile checks. |
| Source and architecture boundaries | Forbidden dependencies, private includes, exported symbols, component ownership, and guarded implementation paths. | Text inspection, C AST queries, symbol inspection, and strict compile probes. |
| IDL, schema, and generated artifacts | A declarative source remains authoritative and every derived representation is current. | Regenerate into a temporary file and compare, or compare registry projections. |
| Numerical expectation data | Stored color certificates and source-value tables agree with an independent mathematical derivation. | Exact rational matrix calculations, binary32 rounding-cell checks, and exhaustive UINT16 normalization and polarity checks. |
| Cross-surface interface consistency | CLI help, manuals, completion, public headers, bindings, build descriptions, and platform metadata describe the same contract. | Normalize each representation and compare complete inventories. |
| Test meta-checks | Tests themselves follow plan, structure, registration, portability, artifact, and source-list rules. | Inspect the test corpus and its Autotools, Meson, runner, and amalgamation registrations. |
| Documentation traceability | Durable policy claims link to their evidence, while exhaustive suite inventories keep every defensive and supplementary test discoverable without turning it into a public contract. | Compare enforced behavioral inventories with reciprocal `Policy:` comments and marked test-plan inventories with reciprocal `Test-plan:` comments. |

IDL-based verification and tests about how tests are written are both first-class `staticcheck` work. The category is intentionally broad because a growing repository accumulates quality risks between files and systems, while ordinary language linters usually see only one representation at a time.

The [comparison dependency check](../../tests/_static/sh/staticcheck-comparison-dependencies.sh) prevents CI from requiring diffutils and verifies the native and source-only fallback registrations. Separate comparison cases run against the source-only implementation without compiling C, checking binary equality, differences, final newlines, empty inputs, input errors, stdin and multi-buffer input. The same files exercise the selected native comparator during `check`; [test harness](../build/test-harness.md) owns its behavior and [platform requirements](../platform-support.md#build-requirements) owns admission of external dependencies. These source checks do not prove availability of every command on every OS; absence-of-tool builds and runtime checks remain necessary.

## Relationship to behavioral tests

`make staticcheck` and `make check` answer different questions. `staticcheck` asks whether the repository is internally well-formed and whether duplicated or generated representations agree. `make check` asks whether built software behaves correctly for concrete inputs, platforms, and feature configurations. Neither subsumes the other.

This distinction is especially important for the test suite itself. Running every behavioral test cannot prove that an unregistered test was included, that a TAP file declares exactly one observation, that the same runner cases exist in normal and amalgamated builds, or that a policy document lists all of its evidence. Those are meta-properties of the suite and belong in `staticcheck`.

Static comparison also cannot prove that synchronized prose is clear, that an option is a good design, or that a C `setopt` implementation produces the intended image. Structural parity prevents accidental divergence; focused behavioral tests and review establish meaning.

## CLI option propagation as a staticcheck contract

The [CLI design policy](../cli/design-policy.md#cli-driven-contract-propagation) treats a public converter option as the change origin for several representations. `staticcheck` turns the mechanically observable portion of that policy into a chain of invariants:

```text
option registry and public optflag
              |
              v
parser -> -H output -> manual -> Bash completion -> Zsh completion
   |                                                   |
   +---------------- C and binding surfaces -----------+
```

The checks compare the complete top-level option inventory of `img2sixel`, including punctuation short forms, across runtime `-H`, its manual, and the Bash and Zsh completion files that the repository ships. `sixel2png` has a corresponding `-H`-to-manual check; it has no completion edge because the repository does not ship completion files for that program. Registry checks cover structured option metadata and its applicable help, manual, environment, and public-header projections. Binding checks compare configured `SIXEL_OPTFLAG_*` names with Ruby, Perl, Python, and PHP constants and keep binding test coverage for loader `setopt` cases aligned.

This chain does not turn one file into the generated source for every surface. It establishes an equivalence class with explicit owners and catches drift at review time. A new representation must either join the chain through a static check or document why its semantics cannot be compared mechanically.

## Running the target

Put repository-local tools first in `PATH`, build the configured tree, and run the umbrella target:

```sh
PATH="$PWD/.local/bin:$PATH" make -j8 staticcheck
```

The Meson build exposes the same umbrella suite through its run target:

```sh
meson compile -C build staticcheck
```

Before dispatch, the Autotools umbrella target asks the owning `include/Makefile` to refresh `sixel.h` and `6cells.h`. Configured-header and IDL dependencies therefore apply even when no C compilation precedes the check; an incremental checkout must not compare current bindings against an older generated header. Failure to regenerate a required header stops dispatch. Direct checker invocations still require their documented inputs.

The suite schedules independent named checks through recursive Make and prints start and completion events immediately on stderr. Complete diagnostic logs remain in deterministic registration order on stdout, followed by a concise pass, skip, and fail summary.

Scheduling and lint pipelines run in the foreground so terminal Ctrl+C reaches their children; temporary workspaces are removed after foreground jobs exit. Each invocation creates its scratch workspace under the source tree's `.staticcheck-tmp/` and passes that path through `TMPDIR`, `TMP`, and `TEMP` to child tools, including out-of-tree builds. This keeps temporary files out of the system temporary directory and outside recursively scanned source directories.

`make staticcheck` runs serially; `make -j8 staticcheck` uses Make's shared eight-job budget, and `make -j1 staticcheck` explicitly selects serial execution. ShellCheck and codespell retain bounded file batches, whose recursive Make jobs share the same jobserver with the suite and other build targets. No independent CPU-count detection or `STATICCHECK_JOBS` override is used. Direct shell and Meson run-target invocations execute the same checks serially because they have no Make jobserver. Every scheduled check is accounted for, including after another check fails; missing worker results fail the suite. Workers share an immutable source-contract inventory and use separate logs. Only the per-file ShellCheck results described below persist between invocations. A failing check makes the umbrella target fail. Some checks require a configured header or built introspection binary; those checks report a skip when the prerequisite is absent, so a run with skips is not evidence for the skipped contract. Optional external lint tools are also reported as skips when unavailable. Use a normal configured build with the documented toolchain when claiming full validation.

ShellCheck stores one successful `.trs` artifact per input path under `.staticcheck-cache/shellcheck/` in the build tree. Make selects stale results from each input timestamp; only those files enter execution batches of at most 64. Batch membership is never part of cache identity, so changing one file preserves the other 63 results, and adding or removing files does not renumber cache entries. Executable bytes, checker implementation and invocation context select a separate cache namespace. Failed batches publish no results; successful results are renamed individually after completion. Result timestamps precede analysis by at least one second so Make implementations with whole-second comparisons cannot hide edits during analysis or in the same clock tick. Very recent inputs may consequently receive an extra check. As with ordinary Make dependencies, content changes must advance source timestamps; restored or backdated timestamps require a forced run.

Reuse is deliberately limited to self-contained shell inputs. Potential source commands and source directives, including quoted or continued spellings, always receive a fresh check. ANSI-C quoted words are excluded conservatively. Custom `SHELLCHECK_OPTS` or any applicable ShellCheck configuration file disable caching for that invocation; arbitrary external dependencies are not tracked in a separate database. Unsupported Make filename syntax or missing cache tools also falls back to fresh checks. Shell style policy scans always run. `STATICCHECK_CACHE=0 make -j8 staticcheck` bypasses reuse, and `make staticcheck-cache-clean` removes persistent results without touching sources. Ordinary `staticcheck-clean` removes only reports. Direct and Meson invocations use the same cache selection and serial batch execution.

For a TAP-producing static check, only standard output is parsed as TAP; standard error is retained separately for diagnostics. The dispatcher requires one leading or trailing plan, consecutive explicit or implicit result numbers, and a result count matching the plan. Missing or malformed results, unknown stdout records, bailout, an unterminated diagnostic block, or a nonzero child status fail the check. A mixture of successful and skipped results passes; only an entirely skipped check is reported as skipped. A failed ordinary result still fails when another result is skipped. TODO does not establish a static invariant and is rejected in this suite. This staticcheck policy does not alter the ordinary behavioral TAP harness.

Failure output retains the original TAP result lines, child standard error, and parser diagnostics. Shell verbose/trace output can contain literal `not ok`, `1..N`, or `Bail out!` strings; because it belongs on standard error, those strings cannot turn a successful TAP stream into a failed or skipped result.

The registry image-coverage check accepts equivalent escaped-pipe shell patterns and complete CMS record assertions without weakening them to partial wildcard checks. It still requires both typed assignments and actual CMS application. Captures must use unique local artifact names and be overwritten by shell `>` or the converter `-o` option, which opens with `O_TRUNC`; append redirection and missing capture destinations are rejected. The converter-owned output path also avoids GNV text-record limits without weakening the image assertions. Short/environment output equivalence can use exact byte comparison or a checked MS-SSIM 0.98 comparison for documented nondeterministic output. Tests whose contract is option routing may instead assert typed values, actual consumers, nonempty output and exact short/environment output equivalence. Time-budget CLI evidence checks the value consumed by presentation under a deterministic pass cap, while injected-clock tests cover deadline behavior. Their explicit `Image assertion: option-values-and-output-equivalence` marker does not claim independent pixel correctness; the checker still rejects missing assignments, consumers, comparisons and nonempty-output checks. Tests that claim pixel correctness additionally need a quality comparison or an independently specified literal pixel reference encoded through the strict loader path. The [test-design rules](guide.md#image-quality-tests) determine which observation is appropriate.

The suite collects source-owned `Staticcheck:`, `Policy:` and `Test-plan:` references in one shared scan. Full files are read so misplaced declarations after line 20 still fail their owning checks. The reference outputs are immutable for the duration of that invocation; focused document checks use the same collector with their own scope. Header/modeline validation reads each tracked source once, retaining the first declaration and last matching line positions instead of launching per-file text pipelines. Git-file worktrees receive the same validation as ordinary checkouts.

During development, an individual Autotools check can be run from the test directory, for example:

```sh
make -C tests staticcheck-docs-bash-vs-zsh-completion
```

The umbrella target remains the completion criterion because a focused check does not expose interactions with other repository invariants.

The color expectation audits also have individual targets:

```sh
make -C tests staticcheck-png-color-oracles
make -C tests staticcheck-tiff-uint16-oracles
meson compile -C build staticcheck-png-color-oracles
meson compile -C build staticcheck-tiff-uint16-oracles
```

Both targets run the [independent oracle auditor](../../tools/verify_color_oracles.py) with the configured host Python interpreter and only its standard library. The PNG check independently derives the stored cHRM exact values, error bounds, and binary32 rounding certificates. The TIFF check covers every UINT16 normalization and MINISWHITE complement, then the separate-plane source tables for orientations 1–4. These checks require neither optional image libraries nor a CMS or built converter. Enable them explicitly with `--enable-staticcheck-image-audits` under Autotools or `-Dstaticcheck_image_audits=true` under Meson; the default is disabled. Enabling the option requires Python 3.9 or newer at configuration time, and a missing or invalid interpreter is an error. The same option enables the separate `staticcheck-png-cms-matrix` audit of PNG chunk CRCs, decompressed raster identity, reference classes and generated matrix tables. Disabled audits report a skip without starting Python. A mismatch fails the target and the umbrella suite. They verify stored expectations, while loader value assertions and final-image MS-SSIM regressions remain separate runtime observations.

The preprocessor portability check scans maintained C sources and headers, including test helpers, for `near`, `far` and `interface` identifiers that collide with Windows macros. Comments and string literals are excluded. It also requires `<stdint.h>`, `<inttypes.h>`, or the public `<sixel.h>` (directly or through a maintained quoted header) before a `SIZE_MAX` fallback definition, because `<limits.h>` alone does not prevent later redefinition. This conservative source check inspects all conditional branches; it does not replace compilation on each platform.

The independent [octal escape boundary check](../../tests/_static/sh/staticcheck-c-octal-escape-boundary.sh) rejects decimal digits immediately after an octal escape in maintained C literals, including tests and examples. MSVC diagnoses both `\0337` and `\0338` as C4125: after three octal digits, even another octal digit triggers the warning. Write `"\033" "7"` or `"\033" "8"` to preserve the ESC and digit bytes without the warning. The shell/awk scanner joins continued lines, ignores comments and escaped backslashes, and checks valid and invalid literal controls without Python or compilation. It does not evaluate preprocessor conditions or replace native compiler validation.

The VM-result handoff check inspects the DragonFly BSD workflow attempts and host validators, with in-memory removal controls for missing capture, validation, retry guards and distinct result paths. Small shell probes exercise stop-on-error, successful artifact handoff after guest failure, host status propagation and rejection of missing or malformed records. It requires neither Python nor a running VM; actual startup, connection and copyback remain CI observations. The [CI infrastructure and artifact policy](../ci/design.md#dependency-and-infrastructure-policy) owns this boundary.

The Emscripten executable-runtime check protects the paired worker-proxy and runtime-exit flags, their platform/thread guards, and their consumption by converter, assessment and test-runner link targets in Autotools and Meson. It uses one awk process with in-memory removal controls and does not compile or launch Node.js. The [platform contract](../misc/platforms/emscripten.md#build-contract) owns the runtime rationale; actual worker reclamation remains an Emscripten CI observation.

The separate compile-time skip check rejects a standalone `return 77;`, `return SIXEL_TEST_SKIP;`, `return 0;` or `return EXIT_SUCCESS;` preprocessor branch followed immediately by unconditional C test code. A disabled test uses an alternative compilation branch so compilers such as PCC do not reject its unreachable body; exclude private helpers with that body to avoid unused-function warnings. A complete diagnostic call before the return is allowed. The awk check inspects function bodies and nested runtime blocks, ignores comments and literals, accepts returns controlled by runtime conditions, and exercises valid and invalid controls without Python or a target compiler. It deliberately does not evaluate macro expressions or prove general reachability.

Ordinary source and registration checks use the host shell, awk and base utilities; they must not require Python to start, enumerate files, dispatch checks or validate source policy. Python binding checks and explicitly selected optional parser and image-audit tools own their separate interpreter requirements. Absence of Python does not waive an ordinary invariant. Test-source enumeration is shared within one suite invocation; this avoids repeated filesystem traversal without caching checker verdicts. Direct invocations retain the same filtering and argument boundaries.

## Adding or changing a staticcheck

1. State one repository invariant and identify its authoritative and derived representations. Do not start from a preferred parsing trick.
2. Normalize only syntax that is irrelevant to the contract. Retain names, argument shapes, scopes, or ordering whenever the policy treats them as meaningful.
3. Prefer a small deterministic check under `tests/_static/`; use a temporary artifact for regeneration or comparison and avoid mutating tracked files.
4. Give the check a `staticcheck-<subject>` name and add it to [`staticcheck-suite.sh`](../../tests/_static/sh/staticcheck-suite.sh), which is the canonical umbrella ordering used by both build systems.
5. Keep the Autotools, tracked `Makefile.in`, Meson run target, and distribution lists synchronized when the check is exposed individually.
6. Add reciprocal `Policy: docs/...` comments when the check enforces a durable subject policy document, and list the check in that subject document's coverage inventory. Do not add every check to this overview; reserve this document's own coverage inventory for checks that maintain staticcheck itself or this documentation contract.
7. Run the focused check, `staticcheck-doc-test-links` when policy links changed, `staticcheck-test-plan-links` when exhaustive suite inventories changed, the full `make staticcheck`, and behavioral tests appropriate to any product code changed alongside the invariant.

Do not hard-code numbered test filenames in a checker to require behavioral coverage or test existence. Keep coverage in the owning document's stable coverage IDs and reciprocal `Policy:` links, or use a marked `test-plan` inventory when exhaustive membership is the invariant; [documentation-to-test traceability](../AGENTS.md#documentation-to-test-traceability) defines those formats. When a property is mechanically observable, scan test contents for that property instead of selecting a test by filename. Runtime comparisons and verdicts belong to the behavioral test; static checks must not require a particular variable name or assertion spelling merely to duplicate its verdict. A rename updates document links and build registration where applicable, while the contract ID stays stable.

A literal test filename is appropriate only when its identity is meaningful, such as an explicit exception allowlist, a fixture used to test the checker itself, or a platform compatibility ledger. Explain that reason near the beginning of the checker and fail with the missing path when a named target no longer exists. A representative behavioral example alone is not an exception to this rule.

Source-only TAP contracts that also run in the ordinary test harness declare `# Staticcheck: staticcheck-<subject>` within their first 20 lines. The umbrella suite registers the stable subject and discovers exactly one marked owner; a missing or duplicate owner fails. These contracts inspect source representations, so running them under staticcheck does not claim an image-processing observation. The PSD diagnostic mappings and k-center preference source contract use this mechanism. Their `Policy:` links below preserve documentation ownership independently of their filenames.

A staticcheck should fail with enough normalized evidence to locate the divergent representation. It must not silently rewrite committed outputs: automatic correction can be a separate developer command, but the verification target remains read-only with respect to tracked repository state.

Both documentation reciprocal checks scan PowerShell `.ps1` comments as well as the existing source languages. The [traceability policy](../AGENTS.md#documentation-to-test-traceability) defines the supported nonrecursive inventory patterns, including `????_*.ps1` for numbered cases beside shared helpers, and the requirements when adding another language. Invalid marker syntax, missing/extra files, duplicate inventory entries and one-sided references are errors. Source descriptions and evidence claims still need semantic review.

The explicitly enabled `staticcheck-png-cms-matrix` image audit validates the [generated PNG CMS matrix](../loader/png-color-metadata.md#maintaining-the-tables) against its input chunks, committed reference bytes, test ownership, and recorded quality floors. Adding or remapping a matrix test requires reviewing and regenerating that shared table.

The independent [test fixture distribution check](../../tests/_static/sh/staticcheck-test-fixture-distribution.sh) resolves literal `EXTRA_DIST` paths and simple Make variable references, then checks every source file under a test `data/` directory against those paths and their ancestor directories. Its controls distinguish exact files, recursive directory coverage and missing sibling fixtures. Unsupported variable expressions fail explicitly; the check neither runs Make nor compiles helpers. The [test harness reference](../build/test-harness.md) owns the release-fixture contract.

The independent [test macro isolation check](../../tests/_static/sh/staticcheck-test-macro-isolation.sh) compares continued, comment-stripped function-like macro definitions across C test sources and records which names remain defined at each file boundary. Differing definitions shared by multiple files fail if any owner leaves the name defined; identical definitions and locally undefined macros are accepted. In-memory controls cover collisions, identical reuse, complete and incomplete cleanup, comments and continued definitions. One awk process retains cross-file state without a large command line, Python or compilation. Conditional directives and included headers are not evaluated; native amalgamation builds remain necessary. The [Autotools reference](../build/autotools.md#library-linking-and-generated-translation-units) owns the isolation rule.

The [WIC probe scope check](../../tests/_static/sh/staticcheck-configure-wic-scope.sh) rejects missing flag saves or restores and restores outside the Windows probe branch. The [unity feature-namespace check](../../tests/_static/sh/staticcheck-test-unity-feature-namespace.sh) checks the common namespace setting on all three Meson C test targets and preserves the DragonFly exception. Both use one awk process with in-memory negative controls; neither requires compilation. Their contracts belong to the [test harness](../build/test-harness.md).

The independent [amalgamation header-scope check](../../tests/_static/sh/staticcheck-amalgamation-header-scope.sh) runs the real generator on a tiny fixture and checks transitive header selection for two consumers plus an unreferenced control. It does not generate the full repository amalgamation or compile it. The [Autotools reference](../build/autotools.md#library-linking-and-generated-translation-units) owns the selection boundary.

The generated-amalgamation-input check runs the generator against a tiny tree before and after adding the generated runner wrapper and selection header. Both outputs must be identical, protecting in-tree incremental builds as well as the initial build. The [Autotools reference](../build/autotools.md#library-linking-and-generated-translation-units) owns this boundary.

The converter-discard check scans shell TAP sources for an `IMG2SIXEL_PATH` command redirecting stdout to a quoted `${variable}` that has no other reference in the file. Such unobserved captures use `-o/dev/null`, following the [OpenVMS record-file contract](../misc/platforms/openvms.md#gnv-and-openvms-boundaries). The check joins continued lines and excludes stderr redirection; it is a literal local-reference check, not shell data-flow analysis. Captures read or compared later remain valid.

The Emscripten coverage check requires every coverage matrix entry to enable gcov instrumentation and install its report reader without also enabling LLVM source-profile instrumentation. In-memory controls exercise both accepted build-system spellings and rejected missing/mixed instrumentation. Runtime counter generation and SDK-reader compatibility remain CI observations, described in the [Emscripten reference](../misc/platforms/emscripten.md).

Independent checks protect separate portability boundaries: Libtool object resolution exercises the native-link wrapper with a substituted DCL command; C test scanning rejects raw `sscanf`/`vsscanf` calls in shared test C sources and headers; VM configure inspection verifies early selection of the build make; generated-header inspection rejects gperf source directives and missing recipe filters. The C scanner ignores comments and literals and excludes standalone extension probes, which do not link the shared CRT compatibility layer. Each check has positive and negative controls and uses shell/awk, without requiring Python or a target compiler. These checks protect source contracts, not native compiler or OS execution.

The independent C stream check rejects direct `tmpfile` and `fileno` calls in shared test C sources and headers. It ignores comments and literals, joins continued call expressions, and excludes fixture data and standalone extension probes. Literal controls distinguish raw calls from the [test harness adapters](../build/test-harness.md#shared-discovery-and-c-test-dispatch). Only candidate files need a second lexical scan; no compilation, Python, or runtime test is added. Macro expansion and indirect function calls remain outside its scope.

The [assessment file-open check](../../tests/_static/sh/staticcheck-assessment-fopen.sh) rejects raw `fopen` calls while ignoring comments and literals. The [converter capability check](../../tests/_static/sh/staticcheck-test-tool-capabilities.sh) scans shell TAPs for direct converter path references before a configured-capability or executable guard, ignoring comments and default-path assignments. The [comparator probe check](../../tests/_static/sh/staticcheck-comparator-absolute-probe.sh) requires an absolute shell-path operand and conditional native-helper selection. Each concern has an independent shell/awk check with positive and negative controls; none compiles code or requires Python. These literal source contracts do not model arbitrary shell control flow, C macro expansion or OS path semantics. The [test harness](../build/test-harness.md) owns their execution boundaries.

The [palette option storage check](../../tests/_static/sh/staticcheck-palette-option-storage.sh) rejects unguarded block-scope static storage in K-means, K-medoids and K-center setting getters and their environment helpers. It permits the named cache declarations and address operands passed directly to `sixel_palette_option_cache()`, while rejecting direct reads, writes and aliases. Its shell/awk scanner ignores comments and literals, tracks nested scopes and checks positive and negative controls without compiling code. This enforces the [cache access boundary](../threading/encoder.md#execution-stages), not arbitrary C data flow, macro expansion or the correctness of the mutex implementation. The existing first-value retention test and concurrent palette-store test under ThreadSanitizer supply runtime evidence.

The CI installer check rejects literal bare command names assigned to `INSTALL` in the build workflow and setup action. Autoconf treats such values as relative paths when generating subdirectory Makefiles. Controls accept explicit paths and command lookup while rejecting quoted and unquoted bare names. The [Cosmopolitan reference](../misc/platforms/cosmopolitan.md#maintenance-checklist) owns the toolchain setting; the staged-install test remains the runtime evidence. This source check does not evaluate arbitrary shell expressions.

The MSVC complete-build check protects the [CI diagnostic policy](../ci/design.md#diagnostic-independence) in the normal and PGO-use Command Prompt stages. Its shell/awk controls reject an omitted C runner, missing default targets, a finite Ninja failure limit, and a missing or delayed exit-status guard. It validates the owned command form without invoking Python, Meson or a compiler. Uninitialized-value and numeric-conversion warnings remain compiler observations; this check prevents their collection from being cut short, rather than attempting C data-flow analysis.

The independent assessment environment check rejects direct `getenv` calls in assessment C sources and headers, excluding only the private snapshot adapter. Its controls distinguish calls across lines and comments from adapters and inert text. The [test harness](../build/test-harness.md#test-coverage) owns this shared-compilation boundary. A separate Metal stream check verifies the generator's owned stdout branch: it must invoke the encoder without `exec` and immediately exit with its status. Controls reject a missing exit, forced success, exec-based termination and intervening file publication. The [support-script reference](../build/support-scripts.md#embedded-metal-sources) owns the GNV execution boundary. Both checks use shell/awk without a target compiler or Python.

The independent MSVC shared-CRT check protects Meson's explicit default and fatal link probe, together with Autotools' shared-build default and effective-flag probe, for the [DLL ownership contract](../misc/platforms/msvc.md#toolchain-and-crt-contract). Controls reject an implicit build-type default, missing clang-cl coverage, a compile-only Meson probe, an inverted `_DLL` condition and warning-only failure handling. A separate configured-pkg-config check protects both build-system exports, the shell usability probe and the TAP invocation; controls reject bare-command rediscovery and reversed or missing configuration. These checks inspect the owned source forms with shell/awk, without executing a compiler or pkg-config. Native Windows runtime tests remain necessary to establish actual CRT interoperability.

The independent MSVC archive transport check runs the production shell adapter with a large synthetic object inventory and a mock native archiver. It checks bounded native arguments, ordered command files, quoting, cleanup and failure status, together with the CI call site. It uses shell/awk and a mock path converter, without Python, Bash, MSVC or compilation; native LIB interpretation remains Windows build evidence. The [test harness](../build/test-harness.md#test-coverage) owns the transport contract.

The independent preparation-capability check protects the [helper-lane test contract](../threading/encoder.md#test-coverage). It inspects the shared capability, the production eligibility branch and planning tests that wait on helper gates or compare ahead schedules. Controls reject a thread-only guard, missing skip, and commented-out guard, while an explicit-serial test remains applicable. It checks these owned source forms with awk, without evaluating arbitrary preprocessor expressions or requiring a compiler. Worker-pointer lifetime remains a compiler-analyzer and runtime-test concern.

The [PTY allocation check](../../tests/_static/sh/staticcheck-pty-open-flags.sh) rejects `O_NONBLOCK` in `posix_openpt` calls in CLI test support. The [shared-header check](../../tests/_static/sh/staticcheck-test-common-header-guards.sh) checks include guards on test support `*common.h` files. The [PGO training check](../../tests/_static/sh/staticcheck-ci-pgo-study-training.sh) verifies the study-tool invocation and failure propagation. These separate concerns use shell/awk controls without compilation. The [specialized decoder source check](../../tests/_static/sh/staticcheck-wic-option-sources.sh) requires WIC and Quick Look to include the option implementation as well as the threading registry; link validation still checks their complete symbol closure.

### Coverage boundary

The DLL declaration check covers source-visible `sixel_`, `loader_` and `stbi_` references and their canonical export declarations. It scans test support headers as well as C files, so the declaration inventory is independent of direct `#include "src/..."` spellings. Literal object-like aliases suppress external references and map renamed prototypes back to their canonical DLL declarations only until `#undef` or the next file. This is not a C preprocessor or linker: references introduced inside included production implementations and configuration-specific expansions still require shared-library build validation, as described in the [test harness](../build/test-harness.md).

Alias removal checks membership and resolves the previous alias into a scalar before deleting its declaration mapping. GNU awk 5.2 can abort on nested array subscripts in a delete expression, so compatibility requires executing the scanner with that interpreter as well as BSD awk and mawk. In-memory controls exercise undefined names and redefinition without preserving a stale alias; they extend the existing alias-lifetime observation.

The suite-registration check covers shell implementations named `staticcheck-*.sh`; inline compile probes remain explicit runner code and are not projected into a second generated inventory. The reciprocal policy-link check proves the behavioral documentation relationship, and the test-plan check proves exhaustive suite membership, but neither proves the completeness or accuracy of prose. Whether a new invariant belongs in staticcheck, whether normalization preserves the right distinctions, and whether a passing static contract has sufficient behavioral coverage remain review decisions.

The output-buffer storage check audits the owned declaration and allocation forms described by the [encoding policy](../encoder/output/encode-policy/README.md#implementation-and-existing-coverage). It uses awk without a compiler or Python. It does not prove arbitrary write bounds; the DECGRI and packet-crossing runtime tests remain necessary.

The DragonFly feature-namespace check scans the Meson target flags and amalgamation prologue with one awk invocation. Its in-memory controls ensure that strict feature modes cannot be reintroduced through either path without detection. It does not invoke a compiler or query the host CPU count; the encoder wire tests separately select an explicit threading policy to keep their parallel observations independent of host topology.
